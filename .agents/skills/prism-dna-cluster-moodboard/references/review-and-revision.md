# 整板审阅与定点修订

当前模型聚类（0.8）先按 [定点修订入口](targeted-revision.md) 区分事实／关系／显示问题；其 `revise_llm_boards.py` 复用冻结卡及原视觉候选，让模型决定成员，不套用下文历史代码聚类的直接替换／改框动作。以下保留板审标准与旧工具的适用范围，不授予自动逐板审阅或在 B 阶段更改事实的权限。

0.5 新审阅采用实际图像盲审：请求只含当前真实渲染板图、成员原图、必要 ID／对象定位／实际 ROI 和可读性信息。上游板名、profile、情绪轴／组合解释、DNA 描述、选图／取景理由、设计感等级及来源推断另存 `audit-context.json`，不进入同轮模型上下文。没有实际第二轮就不宣称模型已读旁表复核；旧 v3／v4 结果保留其原协议意义。

## 审阅内容

1. 先对照原图判断所选对象及事实归属：主物品、同级的其他设计对象都可；不要求居中或面积最大，也不把背景碎片包装成同级对象。再看实际展示，ID／CMF 都可以是整体或代表性局部。局部需具有清楚的造型、结构、材料、纹理、配色或细节表达，而不是只因一小块颜色相近就入板。

   代表性局部不必包含整个对象，也不限于原图已经拍成的特写。ID 局部不能冒称画外整物结构，CMF 不能跨对象拼事实。原图截断、遮挡和不可见如实说明；不因局部面积小就机械否定，但板上必须读得出所宣称的设计关系。不强制每板有局部，也不强制全板整物。
2. 最终展示尺度是否支持宣称关系；放大原图才能看到的微观细节不能假称板上明显。
3. 比较所选对象的形态、比例、色彩、材料质感和细节语言组合形成的设计情绪，并核对实际裁片是否传达板的共同关系。手机、表、车、服装和家具可以同板，木、布、塑料、金属等不同材质也可以同板。逐项差异允许存在，需解释组合为何仍协调；不要求每张局部同时显露全部五维。圆润轮廓配暖浅织物与镜面金属配锐缝即使轮廓相同，也可能表达不同情绪；不要按材料类别或某个光泽值直接推导结论。指出最不一致成员的组合冲突，不能靠裁掉反例宣称协调，也不能只读先前情绪标签或轴值判通过。
4. 6–10 张、同图／同文章／同已识别项目排重、秀场 ≤30% 分别由程序和来源证据核验，不要求模型凭像素认证品牌项目。
5. 单图设计表达与整板关系分别记录。优先有明确比例、构造、配色、材料处理或细节组织依据的素材；低设计表达、主体不清和普通背景分别指出。不能将品牌、价格、摄影精美或简繁直接当作设计感，也不把“塑料／丝绸”等外观写成贵贱门槛。

## 结果

保存 `coherent / needs_revision / unresolved`、逐张保留／替换建议、最弱成员、范围／品质／可读性问题及依据。AI 判断与人审状态分开；`designer_approved` 默认为 false，提供反馈记录／导出入口。

0.3.0 增加独立的共同设计情绪与五维组合说明，以及逐成员 `emotion_combination_supported / emotion_reason`。缺新判据的旧审阅不能授予新版本通过。文字依据来自当前原图与板图，不把候选的解释照抄成独立审阅。

0.4.0 的新审阅同时检查：所选对象资格与事实归属、原图组合情绪、当前裁片的表达、是否隐藏关键冲突。任一缺依据都不能视觉通过。截图回执绑定对象身份、角色、展示类型、取景理由及 ROI；改变这些内容需要新审阅，不能继承旧 PASS。历史 0.3 审阅保留其原版本意义，不伪装已通过新门。

0.5 使用 `blind-concrete-design-relation.v5`：保存 `shared_design_relation` 的具体共同关系及可见依据；每个成员的 `relation_evidence` 写支持点、最强差异、`coordinated/conflicting/unresolved` 和理由；`pair_checks` 至少包含最不一致成员与另一真实成员的比较。不得只用亲和、松弛等共同情绪词或“无明显冲突”充当正向关系。颜色组织、体量比例、表面组织和细节之间可以有差异，解释协调的依据，而非设同色／同材质硬门或固定两维配额。

新候选的 `requires_concrete_relation_review` 强制新门：任一成员／对照出现 conflicting 或 unresolved，缺依据，或无法绑定当前成员与视窗，均不能视觉通过。程序只检查记录完整和结论一致，不能证明文字真的符合像素；因此保留独立实际看图及人工反馈入口。顶层 coherent 不能覆盖具体拒绝，旧 v4 PASS 不能替新候选签字。

每板默认一次真实审阅请求，不将“先盲看”实现为自动两次模型调用。该请求仅核可见秀场状态，项目来源 `source_identity_checks` 未经独立来源证据核实时编译为 unknown；不能为了防提示污染而伪造来源验证。视觉支持可以是来源待核，不等于完整交付批准。

对同簇候选可因取景或可读性问题替换；改变 DNA 或聚类政策需产生新版本重算受影响簇。最多三次有依据的定点修订，仍有问题则交付当前诊断与未决，不把再试三轮当默认流程。

CMF 的观察框只标明事实发生位置，不能直接视为合格展示框。先查看真实裁片：格构、书籍、灯带、前景对象若压过目标表面的纹理或反光，应修订取景、扩大该表面的显示尺寸，或换用同簇可读成员。原图中确有木纹不等于板上木纹清楚；不能用一句“排除背景”代替像素范围处理。多面转折、明暗跨度是否相容须看实际共同关系，不能从单次失败推导通用禁令。

修改 Skill 需记录触发问题、旧输入和旧结果、实际改动及受影响验证。确认已通过的环节可复用，不反复全样本模型回放。HTML 可用性测试、Schema 或来源程序校验均不等于视觉合格。

## 当前执行工具

- `capture_boards.cjs` 对真实 HTML 图板截图，保存板图、图序、ROI 和 SHA；`review_boards.py` 用这些截图及原图执行独立板审。中途审阅传入冻结的 `--observations`，不得引用正在变化的汇总。
- `revise_units.py` 接受具体 `--unit-ids` 与真实 `--reviews`，属于预提取阶段经明确授权的定点补查工具，不由聚类自动调用。对同一所选对象复核，输出独立 `unit-revisions.json`，通过 `--patch` 离线应用；应用前逐项检查旧单元完全相同。换对象另建新观察，不允许把椅子悄悄改成茶几。修订后按同对象失效情绪，同图另一个对象保持；保留修订证据链并重新冻结后才交接聚类。没有模型证据不把提议值写成已观察。
- `cluster_sample.py --view-reviews` 可携带既有取景问题。只在单元、SHA 与原 ROI 完全匹配时降低选板优先级，保留原簇及问题；新显示尺度仍需本轮审阅。不能把一次 `keep=false` 变成永久图片黑名单。
- `revise_boards.py` 根据当前板实审和显式动作计划，应用建议 ROI、同簇备选替换或减图；数量仍须为 6–10，保留原 DNA、簇归属、失败成员和修订理由。新板重新截图并实审；它不会把调整取景写成视觉通过。建议 ROI 适用于范围错误，或审阅因可读性弱／不可读而拒绝的成员；共同关系仍须获得支持且审阅明确给出新框。实际组织、拓扑或材料关系错误不能靠改框掩盖。
- `finalize_boards.py` 核当前板 SHA 后绑定审阅，分列视觉、数量、来源、秀场及人工状态；顶层 `coherent` 不能覆盖逐成员拒绝。修订成员或 ROI 后需要新的实际板图和审阅。合并新审与未变整板的旧审时，交付绑定实际合并文件的 SHA，原新审输入另存；不能拿部分新审回执的 SHA 代替合并结果。
- `render_delivery.py --history-delivery` 保留明确指定的修改前页面；`package_run.py --mode final` 仅用于固定样本已处理且无在途请求时。模型失败可以如实交付为未决，未处理不能包装成已完成。
