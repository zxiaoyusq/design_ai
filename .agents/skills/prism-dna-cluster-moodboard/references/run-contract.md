# 运行合同与产物

## 当前路线：v0.8 大模型分组（2026-10-10）

本节优先于下文历史 v0.2–v0.5 的代码距离／固定独立板审描述。新输入是预提取 Skill 的 design-cards.v1，新入口为 llm_group.py。模型承担模板发现、归并、全卡路由和真实图像选员；代码不选审美成员。阶段 A 全部终态后冻结，阶段 B 不补 DNA。两阶段分别计时和计调用。

默认不自动追加独立逐板审阅，遵从当前用户先看结果的要求；model_grouped、独立审阅和人工批准分列。旧文件、失败与 PASS 保留历史，不能追认成新版本通过。执行细节见 [规模化模型聚类](llm-grouping.md)。

当前合同另登记 `mode=full_catalogue|priority_boards`、目标板数与方向容量（优先模式）、调用预算和分包参数。优先模式不缩小原图样本，也不以候选板数当达标数。A 可显式用 `--reuse-prepared` 搜索指定旧快照，B 使用全部冻结卡；单板反馈走 [定点修订](targeted-revision.md)，不默认全库重跑。按 [评估口径](evaluation-scope.md) 分支报告技术覆盖、实际看图、审阅和人审状态。

“全量高潜”不得用下文七方向 3,824 图历史池代替。当前可明确追溯的旧 13 高潜来源有 6,834 个有效 SHA，原 50 对照仅 32 个在其中；范围、判定版本及既有人工／模型质量冲突分别冻结。执行范围取当次用户授权，历史某次运行许可不自动延续。离线范围清单不是模型执行授权。

## 历史 v0.2–v0.5 运行范围及产物

下文保留旧观察／代码聚类的回放合同，不覆盖上面的当前模式、缓存能力或模型选员规则。

`run-contract.json` 保存实际用户范围、全集来源、抽样政策、板数量、秀场比例、模型配置及本次执行许可。配置必须实际传入脚本，不能只在说明中改变数量。

2026-10-09 首次试跑：旧七方向关联的 **3,824 个非空唯一原图 SHA** 为全集；1 条无本地原图／SHA 的失败引用单列。取消 Top 5，采用固定种子 `20261009` 的 SHA 排序抽取 500 个唯一图。来源方向仅为全集依据，不约束分支或成员。抽样不偏向现有 DNA、旧 PASS 或特定品类。

每板 `minimum=6, preferred=8, maximum=10`，秀场最大占比 0.30。没有足够独立来源的簇继续展示为待核／小簇，来源未决不伪装为已核实，也不抹掉有价值的视觉结果。

## 数据文件

- `pool.json`：原图全集、所有来源关联与 DNA 引用；缺失引用另列。
- `sample.json`：实际 500 图样本，含种子、抽样方法、原图校验与全集摘要。
- 模型请求目录：逐批 Prompt、Schema、附图身份、原始回答、事件／回执和使用量。不得包含认证凭据。
- `observations.json`：以图像和实际对象／表面为单位的版本化聚类观察；原 R5 引用保留，新值不回写旧记录。
- `prepared-manifest.json`（0.5 起）：预提取 Skill 冻结的样本／观察引用、逐图资产与终态统计；失败不是可用缓存，冻结不是视觉通过。聚类用 `--prepared` 校验读取，不自动补解析。
- `clusters.json`：所有 ID／CMF 簇、成员、差异摘要、小簇及未分配原因；标明算法和特征版本。
- `boards.json`：从簇内选出的候选图板和来源／数量／秀场核验。候选板不自动等于独立审阅通过。
- 独立审阅与修订目录：保留当前板图 SHA、阅读输入和真实判断；修订产生新版本。
- `delivery/`：HTML、图像、结果摘要、来源清单与反馈入口。离线包包含浏览所需资源。

存在恢复或修订时，首次 `observations.json` 不等于最终观察。最终交付保存 `result-manifest.json`，指向实际采用的观察、簇、板和合并审阅及其 SHA；渲染和打包显式传入该观察路径。首次失败、晚到答案、有界恢复与单元补丁分别保留，不能因文件名较短就误用旧汇总。

## 来源和范围

原图 SHA 是字节身份，多角度图片仍是不同图片。同项目的多图不贡献多个独立项目支持。文章 ID 只证明来源文章，不能直接证明项目独立；可依据文章具名项目、原图对象和现有项目注册信息登记 `source_supported`，未知保留。

图片 URL 与文章 URL 分开。原图裁片继承 `runway_state=yes/no/unknown`。每板报告已知秀场数、未知数和最坏上界；上界满足配额可以记录保守通过，否则需核实或保持未决。不得把织物、服装或人物一概当秀场。

## 可见观察与设计情绪解释

0.3.0 按用户补充，将设计情绪明确为形态、比例、色彩、材料质感、细节语言共同传达的感受。不同材质可以协调；材料类别、光泽、纹理或功能形态的差异不再直接触发拆板。`design_emotion` 单独保存组合依据、解释、结构化情绪轴、状态及限制，标记为可见依据上的解释性判断。表达文本不进入距离；可比轴也仅用于生成候选，最终仍须实际独立整板审阅。

0.4.0 起，每份情绪解释绑定原图 SHA 和具体所选对象：主物品或与其同级、有独立设计表达的对象均可，不以面积最大或居中作为资格。`primary_subject` 是保留的历史字段名，在新协议中表示该单元所选对象；同一对象的多个单元共享一致的对象情绪，不同对象不得互借 DNA、颜色、情绪或出处。仅有背景小墙面、偶然色块或无独立表达的陪衬仍不能冒称同级对象。证据不足保留未决。

观察侧表保存 `target_role`、`primary_subject`、`evidence_bbox`、`display_bbox`、`whole_appearance` 与有可见理由的 `design_quality`。对象范围、事实范围与实际展示范围分别存储。0.4.0 新增 `display_scope=whole_object|representative_detail` 与 `crop_reason`：整体展示框包含所选对象的当前可见范围；代表性局部展示框包含所声明的局部事实，事实确属所选对象即可，不要求把整个对象重新装进裁片。没有统一的局部面积门槛或局部数量配额，最终看设计表达与可读性。

ID 与 CMF 均允许代表性局部，不限于摄影者已经拍成的特写。ID 局部只描述可见造型、比例关系、构造或连接，不推断整物比例、对称性、全部部件等画外事实；整体 ID 仍要求完整可见。CMF 事实绑定实际表面，不能跨对象拼成虚假的材料组合。`whole_visible=false` 与遮挡、截断限制如实保留。原图用于核对对象及五维组合上下文，实际裁片用于核对入板表达；局部可以突出一种关系，但不能靠隐藏与该情绪冲突的关键特征制造一致。

### DNA 提取与情绪解释的先后关系

0.5.0 将整个逐图阶段交给 `prism-design-dna-preparation`：先完成当次冻结清单，再交接不可覆盖的观察快照。R5、对象／事实／展示范围、整体外观与五维情绪解释按真实来源分层保存；不重复执行已适用的事实观察。原图 SHA 相同但对象、Prompt、模型或取景范围不同不能静默视作同一缓存。逐图内容寻址资产和整份快照可显式复用；自动跨新运行缓存命中调度尚未实现。

默认全部图像为 observed/failed，pending/running 阻止正式聚类；failed 如实列出且不提供候选。明确 `--allow-partial` 的中途诊断保留未处理清单，不能称完整交付。聚类输出的缺口不触发模型；需要补查时登记具体图片／字段及预算，再返回预提取产生新快照。

Prompt v9 在既有 v3 观察结构中加强主辅色关系、明暗／饱和度主导性、材料光学和宏观／微观细节描述。原 v8 与旧 v2 可按真实版本读取，不因文档更新升级为已补观察。可见 facts 与解释分别保存，不硬编颜色百分比或真实触感。

0.5 候选四轴仅粗召回；具体 whole.color、whole.design 与 ID／CMF 分块的共同覆盖／差异用于代表性排序，再按设计表达择优。材料类别与功能部件数不参与这个排序，单一差异不拒绝。所有新候选要求 v5 正向关系盲审，等权差异未校准，不称自动视觉细分或最终相似度。

先按对象／区域提取可见 DNA 事实，再依据形态、比例、色彩、材料质感、细节语言的组合解释设计情绪；可以在同一次逐图调用中分区输出，不代表按预期情绪反推事实。原 R5 提取器、字典和历史结果保持不变；本情绪板流程的版本化观察层会结合原图核验可复用 R5，补足范围、整体外观、设计表达和情绪依据。新增内容不能改标成旧 R5 原本已观察。

0.4.0 使用新观察协议处理多对象和代表性局部；旧 v2 观察继续按原协议读取，不因升级 Skill 就自动变成已核实的局部／同级对象结果。若只改变取景且原事实仍适用，复用事实并审阅新裁片；若改选未观察的同级对象或局部特征范围不符，先做该对象的有界原图补查。新对象不得沿用主物品的旧情绪结论。用户本次仅要求改 Skill，不据此启动模型重跑、改写旧板或发布新页面。

设计感是选板优先级，不是相似距离，也不授予通过。不同品类／材质通过五维协调的组合表达相近情绪；不得用功能部件数、产品名称、材料类别或材质贵贱替代关系判断。

观察字段的枚举与序数锚点由 `observe_sample.py` 的 schema / prompt 定义，程序比较由 `cluster_sample.py` 消费同一版本。读取其当前实现了解精确字段，不另写一份容易漂移的注册表。

模型视觉补充可以携带已知 R5 与原字段引用，但图片是实际证据。项目、秀场和来源推断放在来源侧表；距离函数只选择白名单可见特征。旧事实和新增观察冲突时保留出处与当前采用理由。

紧凑观察预算仍为每图最多一个 ID 单元、两个 CMF 单元；新协议可分别选择主物品或同级对象的整体／代表性局部。允许同级对象不等于每图穷举所有对象，也不提高既定模型预算。不宣称未选对象或全部 R5 字段已经重提，未选不等于不存在。

历史 0.2／0.3 的 500 图重跑保持首次样本及种子不变，在独立目录补充主体和全局观察，原 R5 与首次交付保留。执行中追加情绪定义时，已提交回答保留，仅对有效旧观察补缺少的情绪，其余使用新版协议。该次授权不延伸为 0.4.0 的新一轮 500 图或 3,824 图调用；后续运行另记录实际授权和范围。

未观察、看不清、不适用、确认没有保持不同状态；没有足够共同可见维度时不计算伪相似。仅有同色、同名称或同品类不足以成簇。

## 运行与恢复

新模型保持当前会话授权的 `gpt-6.1-sol / high`；实际执行器、回执、模型／Prompt 版本和时间均保存。历史 DNA 保持原模型身份。复用有效结果不增加模型请求，缺用量不当零。

并发等执行配置需要调整时，保存引用原合同 SHA 的增补记录，不覆盖原合同。全局限额包含观察和独立板审；本轮增补将初始 3 路调为 5 路，依据实际批次耗时缩短等待，图片范围、模型与不自动重试规则保持原合同值。

先检查一小批真实观察是否满足范围、字段和 Schema，再按同版本继续样本。失败批次保留，不自动换样本或无界重发；若有可诊断的输入／协议问题，可保存旧失败并做受影响的有界修订。不得因为抽样试跑权限自动扩成 3,824 图全量调用。

遇到明确鉴权、配额或限流错误先停新增请求，已开始的请求保留各自结果。旧进程的令牌错误不一定代表当前共享登录仍失效：只读核对当前登录状态、刷新时间及后续实际回执后，才能从未提交批次续跑。认证文件和令牌不得写进结果或交付包。

技术恢复与首次执行分开统计。需要恢复无答案的失败图片时，登记具体图片 ID、原失败引用、已变化的执行条件和每图最多尝试数；新请求另建目录，不能覆盖失败回执。本次仅按明确增补将指定失败批拆成 5 图调用，每图一次恢复机会；用量缺失仍记未知，不能计作零成本。

CLI 启动器可能产生原生子进程，超时必须结束本次独立进程组，成功收尾及 Python 中断也要检查子孙是否遗留。旧版本若出现晚到完整答案，先保留首次失败收据及其日志前缀，再独立校验晚到日志、原 Schema、图片身份与实际用量；校验成功可离线恢复，不新增模型调用。用量按原调用身份归并，内部重连的额外未知用量仍保留未知，合同并发上限不冒充已观测实际峰值。
