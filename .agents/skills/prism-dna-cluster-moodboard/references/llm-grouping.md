# 大模型关系聚类：规模、边界与运行记录

## 统一默认与历史兼容

`llm_group.py` 默认 `--comparison-mode unified`，按 [统一生产判断](unified-selection-policy.md) 在原 ID／CMF 全部有效卡上发现、归并、路由和选图；新组 `branch=DESIGN`，原卡分支仅作出处，不给维度固定权重。`--comparison-mode legacy_branches` 显式保留旧双分支路径及 [历史判断原则](grouping-principles.md)。运行模式与实际覆盖都须登记，不通过更名冒充执行。

少量好板目标用 [优先交付](unified-priority.md)。复用旧模板仍可从全部冻结卡跨旧分支召回；旧提名池不成为唯一搜索范围。程序路径可离线验证，但没有实际完成的全库统一调用就不能声称全库已比对，更不据此断言效果改善。

## 与旧方法的区别

旧 v5 是代码根据情绪轴和具体字段差异分组，再用模型审阅；新版 v0.6 中，局部模板发现、跨批归并、卡片路由和真实图像成员选择都由模型完成。程序不以距离或风格分数决定成员，也不替模型按分数删补成员。

`ref/模板聚类` 的实现本身仍有加权距离／完全连接／代表点／贪心选择。这里只吸收它区分主导表达、辅助信号、尺度、共同组合和强冲突的思路，不把代码权重套到新流程。风格部分来自多标签 v3.0.3 的同层候选及可见支持／冲突，不恢复旧知识库中的 confirmed、主次或仲裁门槛。

## 两个阶段的成本归属

阶段 A：原图 + 有出处的旧 DNA → 对象设计卡。一个对象／视图记录七组关系、同层风格、组合情绪和设计感。一次准备后冻结复用；新规则需要新增事实时，仅在 A 补。单卡并不是简单七个枚举，保留具体关系和反证以避免“同黑、同圆、同亮”信息损失。

0.13 的新 B 投影保留七组事实、反证、未知、限制及具体设计依据，移除单图正向情绪解释和设计感等级。这些上游结论不构成跨图关系证据；原卡、原答和 A 契约不改，不为投影重提 DNA。

指定旧快照的 `design_cards.py --reuse-prepared` 按逐图实际请求语义与证据核验复用；聚类始终读 `--prepared`。相同图片名、合法 JSON 或过去模型 PASS 都不能代替兼容核验。规则未变而仅运行调度改进，不要求重提已经适用的单图事实。

0.9 将 B 的 [通用判断原则](grouping-principles.md) 与 A 的事实协议分开加载和追溯。图例教材不进入逐图请求；新增第四个教学案例不修改 A 的实际 Prompt／Schema，也不触发全库 DNA 重提。B 的规则与调用身份另版，旧准备卡仍须按原证据链核验。

0.10 进一步区分“事实已经写出，选组仍放过冲突”与“缺少事实”：前者只改 B 判断，不重提 A。A 0.4 加强了新提取的主导性、视窗竞争信息及证据能力描述，Schema 不变；旧 `--prepared` 仍可核验加载，但不代表已满足新观察要求。A 的新 Prompt 与旧实际请求不兼容，不能把 `--reuse-prepared` 当作跨 Prompt 零调用升级；需要补查时先列有依据的对象／视窗缺口，仅为其安排另行授权的新 A 计划。不要为了更新规则把完整图库再送 A。

新视觉输出先给 `relation_hypotheses` 的具体主导关系、必要条件、允许变化、破坏条件，再给 `candidate_decisions` 的 include／exclude／unresolved 及 compatible_variation／dominant_conflict／uncertain，最后产生 groups。冲突和未决不得入组；每组最难协调成员对须有 coherent 判定。`strongest_difference` 和正向解释仍用于追溯，但不能覆盖前置否定决定。这些裁决在同一次选图内完成，不额外增加独立板审调用。

逐员仍记录 `relation_readability` 的可证明／不可证明范围及 `viewport_competition`。可读性只针对实际附上的原图／冻结裁片；`limited` 可只承担清楚可见的关系，`insufficient` 不得成为所选成员。结构闸门不能自动判定审美真假，更不能把新字段补写进历史原答。定点重选沿用新规则，恢复旧候选证据时仍按历史自己的 Schema 核验。

`--feedback <registry.json>` 在请求中绑定与实际候选相关的未解决问题，并要求 `feedback_decisions` 逐项响应。用户问题依据来源、对象和关系上下文承接，不随板名／目录重置。模型响应是本次判断记录，不自行关闭历史问题；详情见 [定点修订](targeted-revision.md)。

0.11.1 按用户最新要求，将同品类正式板上限调整为 ≤50%。品类是现有视觉请求中对冻结对象的归一解释，不是重新提取 DNA 或新增一次分类调用；按原图成员张数取 `floor(N/2)`。整个组采用同一口径，不按材质、颜色、风格、房间名或取景部位拆类，unknown 不得当新品类。程序保留逐成员依据、分品类张数和阻断原因；超限／未核不进入合格正式板，不自动替模型删补。

发现、归并和路由不按 50% 过滤，提名池也不按单包配额截断；该池不是最终板。模型提名应注意留下关系成立的跨品类候选，再在实际选板、跨窗重选及定点关系修订时落实上限。2–5 图小组仍可作为线索保留，不能冒充比例已达标。旧板及旧视觉回执保持历史含义，不补写新品类或新通过状态；只有实际执行新规则的范围可报告本项检查。

阶段 B：

1. 将原 ID／CMF 卡放入同一发现队列，每批最多约 32 张卡的文本发现模板；保留局部孤立卡与原分支出处，不把32张当作最终类别边界。
2. 有界窗口比较跨批模板，输入共同组合、支持／冲突及代表／边界卡，而非只输入名称；目录过大时建立有界层级。
3. 完整方向模式将全部卡按目录多路由到可能的叶模板；优先板模式直接比较模型选中的少数叶方向。每层候选数有上限；未命中、需要新模板或预算受限保留残余，不把残余等同低设计质量。
4. 每个叶模板的全部卡进入模型文字提名：每包先选，总池超过32卡时幸存卡再汇合重选，最终看图池最多32卡。池已不超过该上限时，不因文字批大小或字符分包机械减半；各包模型实际提名的并集交给视觉阶段，记录是否曾在一个DNA文字窗共同比较。程序只限制容量，不按审美分数选员或强留6图。这个32是跨批候选的预算上限，不是最初发现批次或`card-batch-size`的成板人数边界；早轮未被提名的卡留在台账，本轮不会自动全部复活，不宣称所有候选均被视觉比较。
5. 看图池按默认 16 个候选分窗，模型能选板、拆组、保留小组或拒绝。原图与冻结真实裁片均可核对，不只看缩略图文字。裁切框在 A 决定，实际裁片在此按框生成，不临时改框。
6. 多窗的初选均为暂定；已选及其他提名对象交错参加一次最多 24 候选／窗的跨窗重选，可替换或拆板。DNA 矛盾项隔离，旧组版本与未重新比较的覆盖缺口保留。不做无限搜索，也不保证所有候选对都互相见过。

每个模型决策都能回到当前输入卡、原图、原始回答与模型／Prompt／时间。模型实际看图选择不是“第二次提取 DNA”，也不是独立盲审。用户明确要求参考板效果对照时，另绑定参考图及当前实际板作有界比较，不将选图理由当作独立结论。

## 几千张如何控制成本

设图片数为 N，每图平均有效卡数为 c，提取每批 b 张；新提取调用约 ceil(待补图片/b)，与以后聚类次数分开。统一初始文本发现约 ceil(cN/32)，原 ID／CMF 卡数作为来源覆盖另列，不分别启动完整流程。实际字符容量可能增加分包数。路由成本取决于目录深度与实际多路分支数；视觉调用约为各模板候选数除以窗口容量，再加归并与有界合流调用。**这不是固定调用数或准确率保证。**

例如 6,834 张图片每张平均 2 张卡时约 13,668 张卡，第一轮文本发现约 428 次，并不是 6,834×6,833/2 次全图视觉两两比较；但归并、路由和图像选择还有额外成本。未实际测量，不承诺几分钟完成。用本次 50 图记录实际阶段耗时和用量后再估算全量，不能把小样吞吐线性外推成保证。

并发最多 10，按当前授权设置并受真实限流约束；不为测速重提同图。运行前冻结 max_calls；达到预算保留 partial 和未完成任务，不少报调用或将截断标 completed。只有完全相同输入键及可验证的原始成功回执才可恢复复用，失败不自动重试。配额／鉴权问题停止新增请求并保留在途回执。只增加预算可显式续未发任务，预算修订与旧 partial 报告保留；程序不会主动兑换额度。

### 分包、阶段证据与失败隔离

路由按每卡实际候选前沿比较。不同候选集合可以共用一个请求：附候选描述并集，同时带 `allowed_target_ids_by_card`，逐卡限制输出；不能把另一张卡带来的方向当作本卡新候选。候选描述和卡片共同计入窗口，不截断关系证据；每卡每层最多三路仍是整层总额，不因分窗或多个父节点而倍增。

每层记录计划请求数、卡数／包、单卡包数量、候选容量和剩余调用预算。后续层数取决于真实输出，初始 dry 只给已知成本，不伪造完整精确预测。目录摘要的一个窗口失败只隔离该窗口，保留其子方向；不能因此把整个分支标成无目录。超限、未发、技术失败和正常未命中分别登记。

任务构建时核实它要求模型阅读的证据真的随请求提供。方向比较包含实际代表／边界卡；视觉选员包含原图及冻结裁片。缺输入应在发送前报错／保留缺口，不能靠模型的 `needs_evidence` 推断素材没有潜力。

包内卡号、方向号按当前允许集合约束；本地校验完整覆盖、重复与逐卡范围。发送 Schema 与完整本地约束分离。新阶段／Schema 结构先运行原计划中的第一个任务，成功后再放开并行；明确配置错误停止新增，保留在途回执。Schema 兼容不代表审美规则通过，失败不能通过猜编号／修模型原答变成成功。

## 优先达标板模式

只在用户明确给出少量达标板终点时采用。通用入口 `llm_group.py --mode priority_boards --target-boards <目标板数> --direction-limit <首轮方向容量>`，其余 `--prepared`、预算和显式 `--execute` 同完整模式。板数是交付目标，方向容量是本轮探索上限，不能以代码截断成员板冒充达标。仍保留全部抽样及冻结 DNA，不把目标两板改成抽两批图，也不降低每板设计关系、数量或来源要求。

1. 复用原批次发现与跨批归并的有出处模板。模型分包比较具体关系、允许变化与强冲突，保留每个模板的去向，再结合代表／边界 DNA 汇合选出有限首轮方向。数量上限是试探容量，不是审美评分；参考板提供品质尺度，不限定配色、材质或主题。
   最后几个方向若来自多窗且未共同比较，需以全部剩余方向的具体关系、实际代表／边界DNA和最近选择依据再作一次合流，避免同义方向占满名额；已有单窗共同判断则复用，不额外重复。合流允许少选，不补位；整体超限或失败保留缺口，不把多窗分别通过当作已消除重复。
   此处选择的是可检验的方向假设，不是6–10成员整板：种子是局部发现依据，后续会从全部冻结卡扩展，种子不足成板数不等于方向不足。未附像素、来源项目未知分别留待实际选图／来源核对，不作为此阶段已完成的判定。已有具体强冲突可使某成员不合适，也可否定缺乏共同关系的方向；不能因尚未做后续阶段而循环淘汰。若请求缺少它承诺提供的证据，先修正输入构建，在新版本接续受影响选向，不重跑全部发现或重提DNA，也不改旧原答为成功。
2. 完整冻结卡统一比较已选叶方向，不必先把所有目录逐层走完。旧 ID／CMF 标签不限制新方向候选范围；未选方向、未路由卡及未命中分别登记，不能等同图片低质量或全库没有其他归属。仅复用旧池的小轮另记实际范围，不冒充全卡召回。
3. 复用类内 DNA 提名及真实原图／冻结裁片选组。针对最有希望的实际板作参考像素对照，按具体差距重选或替换；两板不能只是同一成员集合换名。其他板可以未审，未审不算失败或通过；达到用户目标后不继续优化无关板。
4. 旧运行无阶段检查点时，不能强杀父进程后假定子调用已结束。变更目标需先确认实际在途与排队边界，收集已启动调用的终态，核实独立子进程已退出，再冻结主动中止的 partial。只计划未发送、调用失败、身份无效及合法残余分别记录，不伪造原最终报告。

0.7 的 `.runtime/two_board_snapshot.py`、`two_board_target*.py` 是旧1600图运行的冻结接续入口，仅保留历史用途；新运行使用通用模式，不复制其固定板数、图号或目录。新的身份约束和可靠执行不回写旧失败，不能用 `--resume` 把旧 Prompt／源码身份伪装成新版。旧模板复用必须核原请求和证据链，不能仅凭目录里有 `templates.json` 就认可。

通用 `--templates-from <旧分组目录|templates.json|冻结snapshot.json>` 可跳过发现／归并。必须绑定同一 `prepared`，核对历史模型请求、原答、代表／边界卡及模板身份；原局部失败和回退方向另列历史上下文，不能将复用成功称为修好了历史失败。这与同版本 `--resume` 不同；改变准备卡快照后不自动沿用旧模板。

若本次已明确需要扩充的旧关系，可重复指定 `--direction-id <template_id>`。该参数只接受 `--mode priority_boards` 与 `--templates-from` 的组合，ID 必须存在于核验后的模板目录且数量不超过 `direction-limit`；省去再次模型选向，不授予整板通过，也不复用旧成员名额。后续统一路由仍比较全部冻结卡，不能将该方向旧候选池误作新输入全集。

历史模板仅作为有出处的方向假设，不代表已按新版原则校准或发现了参考之外的全部方向。尤其不能用旧的提名／选板结果证明新版反偏置效果；需要检验新规则发现能力时，另经授权从冻结卡做小样新发现，不为验证自动重放全库。

优先模式只生成候选并报告目标尚待实际验收；没有当次独立审阅授权时不自动追加。用户要求参考对照时，对当前目标板做有界实际对照，未达标按 [定点修订](targeted-revision.md) 处理；没有适用候选时返回残余和方法选择，不无限扩方向或偷降标准。

运行中允许改 Skill 不等于允许修改在途依赖或覆盖历史。先记录具体问题及受影响阶段，再验证、冻结新版本后接续；同一成功 DNA 不重复提取。若优先候选均不足，按证据扩展下一批方向或更换选材方法，不靠放宽标准宣布两板完成。

## 已知取舍与改进触发

### 教学输入边界

`references/moodboard-casebook.md` 保存四张原图的解析、允许差异、历史分支边界和假设对照题，按需阅读而不发送到生产聚类模型。统一模式加载 `unified-selection-policy.md`，legacy 模式保留 `grouping-principles.md`，按实际政策保存身份。`--reference-brief` 仅登记来源；其中图例名称、颜色、材料、逐板描述及任意新增字段均不影响生产提示词、候选附件或优先级。候选相关的真实问题通过独立 feedback 契约承接，不借教材混入选材偏好。

用户明确要求效果对照时，再按当次清单实际看参考与当前板。评价对象是关系清晰、差异协调、设计表达和显示可读性，不能以“像某张图例”给候选加分。历史 `.runtime/compare_reference_boards.py` 仅支持其冻结的三参考合同，不因教材增加一图就可当作四参考入口；若另行实现新对照，参考数量、Schema 覆盖与附件索引须全部由当次清单生成，并另版保存，不改旧审阅证据。本轮不新增或自动启动板审阶段。

- 文本卡是压缩，可能漏掉照片整体；因此最终由模型看原图／真实视窗选员。视觉发现遗漏回 A，不在 B 静默改事实。
- 小批模板有顺序及局部性风险；跨批归并、全卡重路由和有界跨窗合流缓解但不证明召回完备。多路由上限与合流提名上限是预算取舍，不是审美规则。
- 当前目录实现是已有模板窗口的覆盖摘要层级，并非模型已对全目录构造最佳语义树；跨窗口仍可能出现重复方向。一次归并、每层最多三路与一次图像合流是当前有界实现，效果要由后续小样及人工反馈决定，不能宣称已解决几千图的所有跨批关系。
- 风格词可能诱导模型；需具体证据与强反证，最终图像阶段不把风格候选当通过结论。别把同风格一律放一板或不同风格一律拆开。
- 模型小组不足 6 张不强凑。如果 50 张样本关系分散可能没有正式板，这不等于应调低一致性要求或暗中扩样。
- 已知同文章／同项目冲突应拦截整组选材结果并说明；代码不能偷偷去掉最低分成员凑出“通过板”。来源 unknown、秀场 unknown 分列，不虚构人工核验。
- 反馈样例用于规则校准。离线 fake tests 只验证执行边界、规模分批、身份与状态，不证明审美准确。需要新图片和设计师反馈才能判断新方法质量。
