# 棱镜｜大模型设计关系聚类与情绪板

这是“先提取／补缺 DNA，再大模型聚类”的第二步。模型发现关系、比较候选并选择成员；代码安排批次、核对身份与约束、保留证据和展示，不以颜色距离、情绪轴或字段平均分决定成员。

开始前读 [统一生产判断](references/unified-selection-policy.md) 与 [规模化模型聚类](references/llm-grouping.md)。按任务补读：

- 接续运行、少量好板或提速：[统一情绪与优先交付](references/unified-priority.md)。
- 具体反馈或重复问题：[定点修订](references/targeted-revision.md)。
- 验证改动：[小样与覆盖边界](references/evaluation-scope.md)。
- 解释参考标准、维护规则或定位案例偏置：[四张参考图例](references/moodboard-casebook.md) 和 [反馈案例教学](references/feedback-casebook.md)。教材不进入生产选图请求。

## 统一判断与冻结事实

`scripts/llm_group.py` 默认 `--comparison-mode unified`：发现、跨批归并、路由、提名和实际选图共用原 ID／CMF 全部有效卡；旧分支只保留出处，不给维度固定权重、不分成两个独占候选池。最终新组的 `branch=DESIGN`，原卡 `branch`、对象、ROI 和原答不改。`--comparison-mode legacy_branches` 显式保留旧分支运行；历史请求仍按其原始契约核验，不改标为统一执行。

消费 `prism-design-dna-preparation` 的 `prism.design_cards_prepared.v1`，先核来源、字节和原答。已经写明的厚薄、体量、纹理、光带或配色冲突，由 B 判断，不要求 A 重提。只有确实缺少对象归属或当前视窗所需事实，才列出有界待补清单；聚类不暗中调用提取器、换框或补写 DNA。

原 DNA 中的单图情绪解释和设计感等级不是跨图协调证据。新 B 请求投影保留七组可见事实、反向信号、未知、限制和具体设计依据，移除单图正向情绪论证及等级，避免反复借用“温和／有序”等结论为选员作证。此投影不修改 A 契约或历史卡。只有原图、对象和实际视窗一致且事实可核验时，才关联同图不同卡；不能把不同对象拼成完整证据。

## 先裁决关系，再产生组

新的视觉选择在同一次请求内依次回答：

1. `relation_hypotheses`：从实际候选提出具体主导关系、必要条件、允许变化和破坏条件。旧标题只是待检验假设，不得为了保留成员不断扩大含义。
2. `candidate_decisions`：逐候选判定 `include / exclude / unresolved`，明确差异属于 `compatible_variation / dominant_conflict / uncertain`。主导冲突或未决成员不能入组；文字上承认冲突后再以同色、哑光、无装饰或宽泛情绪词补偿，不算通过。
3. `groups`：只用已支持同一具体关系的成员成组，核对 `hardest_pair` 确实 `coherent`，避免 A≈B、B≈C 的链式合并。不同关系须另立假设并重新核员，不能仅换宽标题宣布问题解决。

这是选图本身的工作，不另加一轮耗时独立审阅。程序可以拦截自相矛盾的决定，不能替模型证明视觉判断正确。真实图像判断可能失败；结构检查通过不授审美通过。

有具体用户反馈时用 `--feedback <registry.json>` 绑定当前 prepared、真实反馈来源、对象／卡／视窗及相关组合问题；匹配问题进入请求的 `active_feedback`，选图逐项给出 `feedback_decisions`。换板号、换目录、改标题不清除未解决问题，模型无权关闭用户历史问题。精确同对象同视窗的 ID／CMF 别名承接原问题及比较上下文，不能换卡号绕过；别名投影可追溯且原注册表不改。不得仅凭整图 SHA 将另一对象或不同取景一并封禁；反馈不是图片黑名单或参考配色偏好。

## 成板约束

- 跨品类、跨材质允许。比较配色角色、廓形比例、块面、线条、光学、纹理和细节的组合；由当前证据决定主导维度，显著冲突不能被另一个共同点抵消。先关系成立，再优先选具有清楚比例、构造、材料处理或细节组织的设计。
- 主物品或同级对象、整体或代表性局部均可。当前冻结视窗必须支持共同主导关系；不借背景小碎片、不裁去强反证、不外推画外部分。对象归属与视窗竞争焦点分开记录。
- 每板 6–10 张不同原图，目标 8；不足 6 保留小组，不强凑。用户未变更此条件前，不因效果不佳转而放宽数量。
- 每品类最多 `floor(N/2)` 张：6／7 图最多 3，8／9 图最多 4，10 图最多 5。按原图成员数计，非面积／卡数；品类按对象功能统一，餐椅／办公椅同属椅子，不同房间整体装修同属室内空间；局部继承对象品类，不用材料／风格／局部名称拆类绕限。unknown 不当新品类，超限／未核不能称达标。
- 每文章／已知项目最多一张，别名参与排重；未登记项目保持 unknown。秀场最多 `floor(0.3×N)`，未知不当 no。成员由模型选择，代码不自动删掉“最差”成员补足数量或比例。
- 原图证据与图位可读性分开。源图不能证明的微纹理不靠放大解决；仅已有证据被版面压小时调布局。无固定像素门槛，不一律要求整物或简单造型。

## 运行与成本

使用 Python 314，先给计划，加 `--execute` 才调用，参数以 `--help` 为准：

```text
scripts/llm_group.py --prepared <prepared-manifest.json> --out <新目录> --comparison-mode unified --mode priority_boards --target-boards <目标板数> --direction-limit <首轮方向容量> --workers 10 --card-batch-size 32 --visual-batch-size 16 --max-calls <预算> --feedback <registry.json>
```

没有相关反馈时省略 `--feedback`。用户需要完整方向探索用 `--mode full_catalogue`；只需 3–5 张好板时，用 `priority_boards` 复用合法模板、选少量关系方向，并从全部冻结卡跨旧分支召回。旧四池或旧选中成员不能成为唯一范围；只比较了旧池就如实报告旧池覆盖。当前池的独立原图数不足下限只是扩池信号，不是素材低质量。

已明确要扩充哪些已有关系时，可在 `priority_boards` 配合 `--templates-from` 重复指定 `--direction-id <关系ID>`，只省去模型再次选向，仍对全部冻结卡召回；方向须真实存在且不超过 `direction-limit`。复用模板时自动继承源目录的 `feedback-registry.json`，显式新表不能静默删改原问题。统一定点修订的所有类型均须登记当前问题，注册表与计划的反馈来源、定位、类型和受影响成员匹配；空表或其它问题不能代替。`fact`／`display` 仍为零模型处理。

发现阶段读 DNA 文本卡，默认 32 是请求容量，不是成板归属边界。跨批模板归并后，全卡多路由到有关方向；提名再按预算汇合，实际视觉选择比较原图和冻结真实裁片。多窗初选是暂定，要有界合流，允许拒绝或拆组。具体容量、预算取舍与覆盖见规模化说明，不承诺全图两两比较或固定准确率。

并发最多 10，以当次授权为准；无自动重试、兑换或购买额度。预算耗尽、模型失败、未发送与正常未入组分开报告。`--resume` 只复用同身份真实成功回执并续未发任务，不能跨 Prompt／政策变更冒充新判断。变更规则或目标先收齐在途终态，再冻结新版本，保留旧结果与失败。

图片附件须在启动临时工作目录前规范为绝对路径并核 SHA／ROI。缺裁片属于传输范围未验证，不算审美拒绝，也不回 A 盲补。新发送结构先用原计划首个真实任务验证后展开并发；明确 Schema 配置错误停止新增并留痕，不修原答图号伪造成功。

## 交付、反馈与效果声明

输出当前组、板、完整输入去向、约束结果及模型原证据；记录模型、Prompt、执行时间和源图引用。按历史 ID／CMF 来源分列路由、提名、看图的唯一卡／原图及未处理原因，同时说明当前统一比较范围。DNA 可消费、数量达标、功能 QA、实际选图、独立审阅和人工批准是不同状态。

生产统一请求使用 [统一生产判断](references/unified-selection-policy.md)；旧 [通用判断原则](references/grouping-principles.md) 仅供 legacy／历史证据恢复。教材像素和逐板描述不注入生产阶段；`--reference-brief` 只登记来源。候选自身颜色与细节仍是必要证据。规则更改生成新调用身份，不回写旧卡或旧 PASS。

用户要求参考效果时，实际比较当前板的关系清晰度、差异协调、设计表达和显示可读性；不用“像参考颜色／材质”代替质量。未达标先处理具体冲突及候选缺口，不以数量／页面正常宣布完成。没有当次独立审阅要求时不追加长审；当前上下文对照不冒充独立盲审或人工批准。

具体问题持续绑定源证据。事实问题回 A 有界补查，组合问题用当前统一判断重选，显示问题只改展示；详见定点修订。规则更新先做极小离线回归，再以有代表性的有限行为检查核对效果；假模型不能证明审美改善，也不因更新 Skill 自动全库重跑或发布。
