# 棱镜｜设计 DNA 预提取与冻结

本阶段只回答“每张图的哪个对象，实际呈现了什么设计关系”。完成当次全部输入的成功／失败登记，冻结后才启动模型聚类。原 R5、旧观察、原图及原始回答不覆盖；新增关系和风格是有出处的扩展，不冒充旧 R5 原本已有的事实。

开始前阅读 [可见设计关系协议](references/relational-design-policy.md)。执行器为 `scripts/design_cards.py`，使用项目 Python 314；旧 `freeze_prepared.py` 与 cluster 目录的 `observe_sample.py` 仅用于历史 v3 观察，不能把它们的输出改名成新设计卡。

需要解释参考板或维护观察方法时，按需读 [图例教学](../prism-dna-cluster-moodboard/references/moodboard-casebook.md)；它示范事实到关系的推理，不是逐图提取的附件、填空模板或选材偏好。中性记录当前对象的配色角色、比例、块面、线条、表面与细节及反向信号，不为接近参考的颜色／造型而遗漏其他突出特征。空间本身可作为明确设计对象；产品不借背景、光照或邻近物的颜色质感。

## 范围与复用

冻结原图清单、实际字节 SHA、旧 DNA 引用、规则和模型版本、预算、批量与并发。全部指当次清单，不是未经授权的项目全库。修改 Skill 不自动授权模型任务；明确“改完再跑”按上下文有界样本执行，不隐式扩大到几千张。

先检查已有设计卡是否覆盖当前对象、视窗和规则。符合的结果可显式复用；只有旧 R5 时复用其可见事实，补缺失的关系与风格，不重提全部 192 字段。旧记录缺少本版必要维度可能需要补看全部样本，这须如实说明，不能只说“缓存命中所以没有提取”。

跨运行使用可重复的 `--reuse-prepared <旧prepared-manifest.json>`，执行器仅在显式指定的冻结快照中逐图建立复用索引，不扫描未经指定的全库。核对同一 image_id、原图 SHA／路径、旧观察上下文、实际 Prompt／Schema／风格目录／模型及来源；对象与取景沿用通过核验的原卡，原答指针和回执必须有效。样本顺序或其他图片变化不阻止兼容单图复用；异名同字节、移动路径、规则变化、旧证据变化或无法验证的记录不能只凭 SHA 命中。纯调度代码更新不自动要求重提，但也不改旧调用的源码身份。

命中、未命中与拒绝原因写入新计划，只给未复用图片安排新请求。复用旧卡不等于补齐了新规则或新对象；新事实仍需单独授权的 A 阶段补查。`--resume` 是同一计划续跑，不能替代跨运行兼容性核验。

教学版本、B 阶段成板原则与 A 的事实提取契约分开。0.4.0 将实际 A Prompt 升为 v2，补强主导表达、展示窗竞争信息和证据能力的记录，七组 Schema 与共享事实协议保持不变；增加／换序／替换教学案例仍不改变 A 请求。

0.4.1 只澄清消费边界，不修改 A 实际 Prompt、Schema 或请求身份。单图的“温和／有序”等情绪解释、风格支持和设计感等级是该对象的推断，不证明它与另一图片协调。B 统一比较时投影保留原可见事实、反向信号、限制及具体设计依据，去掉单图正向情绪论证和等级；原 DNA 与证据链完整保留。B 已知冲突判断失当不要求 A 重提，只有真实事实缺口才有界补查。

历史 v1 冻结卡经核验后仍可直接交给 B 的 `--prepared` 消费，保留其原始 Prompt 身份，不声称已经按 v2 补齐。A 的 `--reuse-prepared` 则要求实际提取请求兼容：v1 不能命中新 v2 缓存，即使图片与 Schema 相同。若把旧全量清单传给新版 A，会为未命中图计划新调用，不能称为全库零调用复用。先只读列出影响当前任务的具体事实缺口及已有依据，排除纯组板判断和显示布局问题，再对确需补看的有界清单执行默认 dry run；计划不是重提授权，不自动全量或追加模型调用。

## 从事实到设计卡

1. 选主物品或同级、有独立设计表达的对象。允许整体与代表性局部；禁止为相似挑背景小墙角。保存对象框、事实框、展示框及限制。当前紧凑预算每图至多 1 个 ID、2 个 CMF，不宣称穷尽所有对象。
2. 先记录七组可见关系：配色、廓形、块面、线条、光学、纹理、构造细节。每组有观察、证据、unknown。先说明主导表达，再说明次要或偶发特征，不用小圆角、细边或同色局部抹平显著厚重、交叠与纹理差异。两个分支都保留整对象上下文，CMF 另明确表面尺度与光学；同图 ID/CMF 事实只有确属同一对象、在当前展示窗适用且由原图核实时才能参考，不自动串入空间全图、另一对象或框外事实。
3. 再依据事实提取 0–5 个同层风格候选，记录支持与冲突。借鉴 `ref/multimodal-design-dna-multitag-extractor` v3.0.3 的 38 个 active style，协议优先于知识库中旧的 confirmed／仲裁条款；不设主次、不强填候选、不把分数当校准概率。原多标签 Skill 的唯一主物品限制不搬到本扩展：同级对象由用户明确允许，须逐对象绑定。
4. 解释组合设计情绪，并保存反向信号；另记录有可见依据的设计感。对象配色与当前 `display_bbox` 内的陈设、光晕、文字等竞争信息分开：后者有可见影响时写入 `design_emotion.counter_signals`，在 `limitations` 说明归属、遮挡或可读性限制，必要时在 observation 区分。非对象信息仍可能影响显示，不能借为对象材质，也不能因归属不明就把显著色面当成阴影。无干扰时不强填。品类、真实材质、品牌／价格、拍摄精美和简繁都不是设计感的替身。
5. 在 `limitations` 具体说明证据能支持什么、不能支持什么，例如廓形与大色块可读但微纹理、窄接缝不可辨；放大不增加原有证据，模糊不等于光滑或没有细节。部分关系可读时保留其事实，不把整对象一概判为未知。现代服装的肩线、剪裁和分片同样可以结构化。
6. 原图优先于旧文字；冲突保存旧引用及采用的新证据。看不清为 unknown，不是“没有”。一个对象无效要隔离到该对象，不丢同图合法对象；失败不偷偷修值或伪造原答案。

## 执行和冻结

`scripts/design_cards.py --sample <sample.json> --prior-observations <旧观察.json> --out <新目录> --batch-size 1 --workers 10` 先显示计划；有适用快照时追加 `--reuse-prepared <旧prepared-manifest.json>`，可重复指定。加 `--execute` 才执行冻结／未命中图的实际调用。以 `--help` 为准。独立 CLI 默认沿用 DeepAgents + 原模型运行器，gpt-6.1-sol / high；无自动重试，支持最多 10 路，实际规模与并发以当次合同为准。逐图请求便于独立调度和失败隔离，不保证单图请求一定比小批更快。

工程 `/dna-v2` 网页入口由 `backend/app/services/dna/preparation.py` 调用原生 `run` 并显式注入工程 DeepAgents 执行器和运行配置。模型从工程目录选择，连接只读取统一配置；当前网页默认 `gemini-3.8-flash`，不通过 Codex CLI 或 ChatGPT 登录转发。Prompt v2、Schema、可见关系及原生冻结规则共用，模型、参数、实际执行器与依赖身份进入新计划、缓存身份和回执；不修改共享全局模型或将跨模型／跨执行器结果当作兼容缓存。SDK 未显式设置推理强度时记为 null，供应商报告的实际模型／别名原样保留。0.4.2 增加这一工程执行入口，不改变提取 Prompt 或把历史 Sol 结果重标为 Gemini。

每次调用前登记唯一尝试，逐批保存结果及实时进度，运行目录加独占锁。配额／鉴权故障停止新增并收集在途结果；未发送与失败分列，不提前冻结。确认恢复后用相同参数加 `--resume --execute --resume-after-quota-reset` 只续未发请求，已经尝试过的失败图不重提。重置额度必须另有本次用户授权，不因 Skill 默认兑换或购买。

成功门槛按当次约定登记，不当作准确率：2026-10-10 的 1,600 图运行要求有至少一张合法可追溯卡的原图数严格大于 90%，即至少 1,441 图；正常执行仍对全部样本各尝试一次后冻结，ID／CMF 覆盖分别报告。该门槛不是其他项目固定默认政策。

保存原请求、原回答、回执、Prompt／模型／时间及每卡 JSON pointer；输出 `design-cards.json` 和 `prepared-manifest.json`。每图必须有终态，允许“部分对象有效／部分无效”；只把有效卡交接，失败和缺口保留。加载时核对样本、原图和结果 SHA 及原答指针，技术冻结不授视觉通过。

交给 `prism-dna-cluster-moodboard/scripts/llm_group.py --prepared <prepared-manifest.json>`。聚类阶段可以看已冻结真实视窗来比较选图，但不能补写单图 DNA、临时换框或自动重新提取；缺事实时写待补清单，再按明确范围回到本阶段产生新快照。

## 完成说明

分别报告原图总数、有效卡／无有效卡／对象错误／待处理数、复用范围及拒绝原因、真实新调用、耗时及未补缺口。按 ID／CMF 分列可消费覆盖，不把有一张合法卡的原图比例称作全部字段或审美准确率。完成不表示全部成功，风格支持不表示成板支持，设计感也不等于人工通过。分阶段主要节省后续聚类试验重复解析；第一次补同样多图片不会因改名就自动加速。
