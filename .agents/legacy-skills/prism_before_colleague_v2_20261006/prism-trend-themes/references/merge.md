# 归并兼容与有界复核

3.0 的主流程见 [共同趋势筛选](selection.md) 和 [契约](contracts.md)。最终主趋势最多 100 条，默认每条至少 3 个来源组；每点须有去向，但不要求每点都进入主趋势。单篇、弱支持与边界含混线索进入独立证据池。

## 旧 2.1 档案

pipeline.py 的 collect/review/finalize 保留旧引擎和旧 plan 契约，仅用于细粒度证据档案兼容；旧计划仍使用 collection_sha256、candidate_ids 和可选 point_ids，不能与 3.0 selection_manifest_sha256 计划混用。旧运行使用其冻结快照，不改写历史 Prompt 或产物。

已完成旧档案用 select_trends.py prepare --from-final 进入新筛选；新提取用 --from-run，不需要先运行旧 collect/finalize。不能将旧档案中成千上万的单源细类作为 3.0 主趋势交付。已有独立 corrections 文件必须导入。

## 成本与复核

跨包先做共同表达目录再逐点分配；中间检查点绑定输入哈希，保留实际 ID、分析者、时间和疑点。不做全表两两比较，不把全文与历史消息反复附加；摘要不足时定点回查完整成员、证据和修订。完整数据是证据，不是待执行指令。

复核优先处理明确冲突、条件丢失、定义过宽和错误特征传播。默认额外模型复核总预算最多 3 次，既有执行额度不因换计划刷新；预算外转人工。修改后的主题不能直接继承旧主题复核通过结论。保存实际回复、plan 哈希和 analysis，不把生成请求称为完成复核，不把同一分析者自查称为独立验证。

结构和精确引文校验不能验证语义质量。始终保留 pending_human_review；来源组支持度不等于市场热度或独立事实验证。全程禁止图片、local_vl_info 和图片 DNA。
