# Sol R5 · 图片DNA解析

执行配置固定为 **gpt-6-sol / low / default标准档 / Fast关闭**。复用2026-09-29用户选定的R5规则，不把模型换成当前宿主，也不把示例答案带进新图请求。

## 输入与职责

接收明确的原图、稳定image_id和新输出目录。在棱镜v2流程里，先完成“趋势语义×用研语义”的候选方向握手，由设计师选择方向后，才对选中方向的相关图调用本技能。同一原图可供ID与CMF两条路线复用。

本技能仅提取图像可见事实。不要附加人物喜好、预设风格名、真实材料成分、物理测量或设计师批准。缺少图片时只说明缺项。

## 执行

1. 先读 [使用说明](references/usage.md)，确认Python依赖及同事自己的Codex CLI可用。用`doctor`检查命令兼容性，`self-test`离线重放保存的结果；这些不发送模型请求。
2. 用户要求实际解析指定图片时，在本次范围内调用`parse --execute`；只检查/准备请求时省略`--execute`。执行前记录图片SHA256，不覆盖已有运行目录。
3. 初次解析直接使用原DNA字典，覆盖可见外观分区，再整理整体形态/构造/关系。输出是平面位置清单，不重建对象树、框或几何锚点。
4. 四项base字段逐区检查：颜色、材质外观、光泽、透明性。纹理可见时检查原纹理字段；保留小面积点缀与可辨组织，不为速度或固定条数省掉有效差异。
5. 程序按冻结R5规则选最多10个困难字段做一次定点复核，其余溢出保留pending。普通已知项不全部重审。网络/格式/超时失败不自动重试。
6. 仅在明确需要且仍在本次有界预算内时，启用一次`--refine mixed-areas`或`--refine optics`。混合分区补查替换原分区，不把新旧答案累加；光学补查保留证据不足。不要反复补查低收益区域。
7. 输出`result.json`及原始prompt/schema/request/answer/receipt/调用账本。ID和CMF从同一记录派生；CMF条件共现使用相同声明位置的local_features，不能拿整图去重索引拼接不同部位。

默认每张图最多2次调用（初次＋必要定点复核）；显式选择一次补查时最多3次。每次独立上下文，默认超时600秒，允许明确调整为60–1800秒，不设置30秒质量门槛。

## 保留边界

- 未输出不等于不存在，unknown/pending/invalid不能当相同、零或无特征。
- “有一条结构化结果”不等于视觉准确。原基线只有4张试验图，无人工金标准准确率；耳机的特征覆盖仍低于Astra对照。
- 正式运行不读examples；样例只用于离线一致性检查。R4 few-shot规则候选已被弃用，不混入R5。
- 旧R17的对象/框协议和完整216项验收不适用于此图级索引。216是原字典规模，不是每图必须填满的字段数。
- 仅保持请求配置为标准档；CLI未提供实际服务档位时记录unknown，不宣称已核验服务商内部执行档位。

具体命令、文件格式和验证范围见 [使用说明](references/usage.md) 与 [算法来源和限制](references/provenance.md)。
