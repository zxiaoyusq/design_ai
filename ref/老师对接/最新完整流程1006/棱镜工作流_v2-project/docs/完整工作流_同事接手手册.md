# 棱镜完整工作流与同事接手手册

版本 2.0.0 · 2026年10月6日 · 17个小Skill组合

这套流程解决的是：从大量趋势图文和用研报告里找到有依据的设计方向，再把方向转成可见、可比较、可追溯的ID风格或CMF情绪板。输入不是几张已经挑好的图，输出也不只是排版好看的拼图；中间要交代方向为什么成立、图片为什么适用、解析到了什么、哪些内容不知道、如何裁切，以及整板为什么能归为一组。

本版是实际工作复盘和可复用的技能交接，包含已运行算法及辅助代码、输入输出合同、真实局部试验和离线测试。不声称今天重新跑了一轮全库或付费模型。新任务依然需要同事的原材料、模型环境，以及实际的语义和视觉判断。

## 先看完整主线

趋势文章文字 → 趋势纯语义聚类与库内排名

用研原话 → 角色／对象／正反态度整理 → 用研纯语义聚类

两侧语义 → 第一次握手H01 → 候选方向 → 设计师选择或当次授权AI代选

已选方向 → 可见关系和选材说明 → 多独立来源的广候选池 → 原图DNA解析 → 当前对象与位置绑定＋当前目标品质

ID路线：整体轮廓、比例、结构关系 → 第二次视觉握手与选组

CMF路线：指定表面、色域、纹样、光感、相邻界面 → 第二次视觉握手与选组

候选组 → 合适取景／必要展示增强 → 约10张精选 → 实际整板独立审阅 → 内嵌图片HTML与证据交接

独立测试与定点改良贯穿各步。裁切不是只能在末尾出现：素材有合适局部但全图干扰大时，可提前裁切救援；只要对象或范围改变，就重做受影响的绑定、品质与组合审阅。

## 三个必须对齐的意思

**第一次握手只处理语义。** 趋势侧的文章含义与用研侧的原话含义形成候选方向；用研报告里的图片不再作为第一次聚类的输入，更不能由同页图片推断用户喜欢哪些DNA属性。

**候选图数量和最终图片数量是两件事。** 约10张是最终情绪板的展示量，不是只解析10张。解析的候选池应更广，并覆盖多个独立项目、代表视角和合理变化。30/100是我们做过的比较实验，不是已经证明的普适最优值。

**第二次握手是视觉选组。** 已选语义方向和用研边界仍然保留，但这一步需要原图、DNA已知事实、当前目标品质和可见家族共同支撑。ID看整体，CMF可以看局部；不是把两个主题名字再匹配一次，也不是再拿用研图片聚类。

## 角色怎样分工

用研同事负责原始材料和人物身份；趋势同事负责文章库和语义目录；设计师负责选向和视觉目标；解析与品质环节提供有位置的事实和适用范围；ID/CMF环节选组；独立审阅者检查实际成板；主任务维护范围、证据和改良清单。一个人或一个助手可承担多个环节，但作者选择与独立复核必须如实区分。

我们此前获得过“人确认由AI代替”的明确授权，所以历史选择标记为AI代设计师。此授权不随技能包自动转给同事。新的项目如果由设计师选择，就等实际选择；如果明确授权AI代选，就记录授权与真实角色，不制造人类批准。

## 每一步怎样执行

### 00 · 冻结项目范围与运行方式

对应技能：[prism-run-contract](../skills/prism-run-contract/SKILL.md)

输入：当前用户的设计问题、资料范围、已完成产物、分支和预算。短指令有效，已明确的条件直接继承。

实际操作：

1. 说明最终要什么：ID还是CMF、需要几个方向、每板目标图数与上下限、交付形式。把候选池容量独立设置。
2. 登记端到端运行、历史重放或单板视觉试验。模式决定哪些门实际执行；单板试验不能补造H01来假装全流程。
3. 冻结模型、规则版本、输出目录、实际调用预算和审阅责任；记录同事自己的执行环境。把尚缺材料变成明确待办，不用猜测填空。

输出：project.frozen.json、state.json、阶段依赖和资料清单。

验收与回退：未明确的新费用、外部写入或代选权限保留为准备状态；必要本地可逆操作已有授权就直接做。

实际经验：本任务一直保留Fast关闭；R5主干固定Sol low/default请求档，实际服务档位若未暴露就写unknown。

### 01 · 还原用研证据

对应技能：[prism-research-intake](../skills/prism-research-intake/SKILL.md)

输入：原始PPTX/PDF/文字报告、匿名person_id与source_id的对应关系。

实际操作：

1. 保全原文件、原话、图片字节、页码和版面位置。同图在不同人的报告中出现是多条出现记录，不能因图片SHA相同删掉人物关系。
2. 查看原页，把问题、可选答案、填写答案、品牌印象、愿望、举例和分析者笔记分开。报告整理文本不能写成逐字访谈。
3. 完整保留“但”“太”“不”、程度、指代对象和上下文。照片是回链，不是喜欢其全部属性的证据。

输出：raw-evidence、媒体出现表、来源SHA、reviewed研究输入；草稿尚未reviewed时不能进正式语义结果。

验收与回退：缺页、对象不清、版面未核对和人物身份不明分别记录。

实际经验：“边框可以亮、背板太亮”不能被归纳成“喜欢亮面”或“排斥所有光泽”。

### 02A · 用研纯语义聚类

对应技能：[prism-research-semantic-clustering](../skills/prism-research-semantic-clustering/SKILL.md)

输入：核对后的原话、人物、角色、对象、正反态度和范围；不读图片像素来决定偏好。

实际操作：

1. 以含义而不是同词归组，保留每条原话的全部去向。多义原话可以分量进入不同簇，但说明其余含义和限制。
2. 区分多人直接支持的共同偏好、单人探索线索、存在条件或分歧的设计议题、背景主题。人数按人去重，品牌印象和仅提及不计直接设计支持。
3. prepare冻结→模型形成真实提案→原生accept/verify验证引用、角色、覆盖和计数。向H01交完整dataset和run，而不是只有一句supported摘要。

输出：语义簇、原始单位、覆盖台账、正反/条件/未知、可复验的run目录。

验收与回退：聚类数由材料决定，不固定五个簇或五个人。不输出市场占比。

实际经验：用研语义可以宽，但宽泛方向仍需原文依据；AI不得临时造一个“大家喜欢黄金”的主题。

### 02B · 趋势全库语义聚类与排名

对应技能：[prism-trend-semantic-clustering](../skills/prism-trend-semantic-clustering/SKILL.md)

输入：文章文字目录、article_id、来源、日期、标题/全文或摘要，以及供后续使用的图片关联旁表。

实际操作：

1. 保留text_kind：原文、可靠摘录、存档释义或模型摘要。缺全文的条目不能宣传为已经逐篇读过网页原文。
2. 逐篇给出主语义归属、锚点和理由，再做全目录同义合并与边界复核。未归组、待定和次级关联不丢失；代表例句不限制整个成员池。
3. 按受支持主成员规模形成库内排名，同时给独立项目容量和资料缺口。语义颗粒度不能细到只有一篇文章的四张组图能够支撑一板。

输出：corpus、trend-clusters、text-catalogue、ranking与coverage；H01读取完整接口。

验收与回退：排名是库内支持规模，不是市场热度、销量、增长或商业潜力。合并粒度要靠共同含义，不靠数量压力。

实际经验：历史冻结目录为8,833篇图文、45,531个图片关联、190个一级主题；这些是当时库的统计，不是每次任务的输入要求。

### 03 · 第一次握手：趋势语义 × 用研语义

对应技能：[prism-h01-semantic-handshake](../skills/prism-h01-semantic-handshake/SKILL.md)

输入：趋势簇＋逐篇文字证据，用研簇＋完整原话/角色/正反态度；当前设计问题与握手档位。

实际操作：

1. 以两侧具体内容对齐，不只比较簇标题。每个候选说明共同设计原则、支持来自哪里、适用对象以及哪些部分是延展假设。
2. 保留consensus共识、extension延展、exploration探索三档的允许范围；档位变化不降低原文和负向审计要求。
3. 逐一核对每条原始否定对每个候选的适用性，并保留未来产品的未决义务。未聚类否定也要审，不能批量改成not_applicable。
4. 原生accept/verify完成协议与引用审计，再呈现候选供选择；协议通过只代表检查范围通过。

输出：candidate-directions、accepted、完整negative_audit/deferred_obligations和双侧证据引用。

验收与回退：此时不做图片DNA或高级感，不输出无标定的“高潜100分”。

实际经验：后续CMF局部参考不能凭宽泛的未来手机限制被整批否决，也不能把限制删掉；要保留原对象与适用阶段。

### 04 · 选择方向并分配路线

对应技能：[prism-direction-selection](../skills/prism-direction-selection/SKILL.md)

输入：H01候选、支持范围、矛盾/未知、独立文章来源容量及设计师判断。

实际操作：

1. 让选择者看见每个方向的语义依据、潜在设计空间、素材容量和风险，而不仅是一个好听的名称。
2. 实际选定方向和ID/CMF分支，记录选择者、理由、授权或真实确认。也可以同方向走两个分支，但图片比较单位不同。
3. 使用原H01 select保留候选身份和完整边界。不得因为旧DNA缓存更多，就只选以前解析过的方向。

输出：可复验selection、decision-log、未选理由、H01引用和分支。

验收与回退：六方向、三ID三CMF是一次用户指定配置；新项目按当前需求。候选不足明确缺口。

实际经验：历史“方向太细、还要后台不停回找素材”的问题，应在这一阶段就用容量信息暴露。

### 05 · 把语义方向写成可见关系和选材标准

对应技能：[prism-visual-family](../skills/prism-visual-family/SKILL.md)

输入：已选方向、用研边界、设计师PDF/参考板、图数政策及低成本真实预览。

实际操作：

1. 明确设计转译：例如一个用户语义问题，可以探索若干不同造型关系。不要把某条造型路线伪装为用户直接表达的偏好。
2. 写比较单位、共同主关系、必要证据、允许变化、容易混淆的信号、取景尺度和来源容量。ID关注整件；CMF关注表面或同物件界面。
3. 在大量解析前用真实预览检查能否在多项目中落地；给出每类图片应该保留全貌、裁哪里、补什么或怎么增强的条件。规则在正式筛选前冻结。

输出：visual-family/material-brief、count_policy、原生brief所需引用与负向边界。

验收与回退：不能把“都黑色”“都是椅子”“都是可持续”当视觉一致性。规则变更需新版本，不事后改标准。

实际经验：线性槽纹试板的低彩度和至少五条起伏是该方向规则，不是所有情绪板的通用门槛。

### 06 · 建立广候选池并给每张素材处理计划

对应技能：[prism-source-image-selection](../skills/prism-source-image-selection/SKILL.md)

输入：已选趋势成员、视觉家族、跨品类延展政策、明确的文章/图片清单。

实际操作：

1. 从选中语义方向的成员池召回，扩展参考必须单列身份与关系依据。先看原图，不以文章标题、关键词或旧DNA描述替代视觉判断。
2. 为每个素材保留原文、图序、URL、原图SHA、像素和项目/系列证据。同来源多视角可以进入候选，最后每板同项目只留一张。
3. 逐图写当前对象、具体区域、共同关系的可见证据、第二强干扰信号、建议ROI和处理动作。图片主角未必是本次要用的对象，换对象必须重新审。
4. 冻结解析候选池和分母；候选量由覆盖、差异与预算决定，不从最终10张倒推只解析10张。

输出：metadata-pool、原图manifest、material-plan、冻结DNA候选池和未通过/待补资料清单。

验收与回退：像素不足、关系不清、目标错误、格式失败和家族不适用不能合并叫“不典型”。不在后台无限回找。

实际经验：30/100比较中两档最终仍只出10来张；多解析可以增加选择空间，但单次AI盲评没有证明100普遍优于30。

### 07 · 原图DNA：主解析＋必要定点确认

对应技能：[prism-dna-sol-r5](../skills/prism-dna-sol-r5/SKILL.md)

输入：冻结候选池中的原图、稳定image_id、SHA和R5规则。语义方向用于确定解析哪些图，不用于强迫图中存在某特征。

实际操作：

1. 同SHA、同规则的已有完整记录可以复用，保留已知、pending、invalid和原始执行链；没旧DNA不妨碍进入新解析。
2. Sol R5覆盖可见外观分区与整体形态/构造，保留位置at及原字典编码。逐区检查颜色、材质外观、光泽、透明性与适用纹理。
3. 冻结规则对困难项进行一次有界确认；默认每图最多2逻辑请求。显式额外refine才适用另行登记的更高上限，不能默默扩大。传输失败不自动无限重试。
4. 原始prompt/schema/回答/解码/账本一起保存；compact wire只是外层传输，不改内层规范和原字典。

输出：portable result.json、local_features及索引、pending/invalid、原始输入输出回执和字段来源。

验收与回退：216是字典规模，不是每图必须填满。partial允许有用已知项，不升级成完整准确；实体材料、工艺和物理测量无证据仍未知。

实际经验：2026-10-03的500新图最终486可消费已知范围；422经过第二逻辑确认/修复。97.2%不是视觉准确率，12.8%单调用产出率也不是整个R5流程的成功率。

### 08 · 把DNA绑定到当前比较对象

对应技能：[prism-target-view-binding](../skills/prism-target-view-binding/SKILL.md)

输入：原R5记录、原图、material-plan、视觉brief及待完成或已完成的品质范围。

实际操作：

1. 原R5是平面位置索引。实际看原图，把所需观察绑定到它自己的at、observation_id和当前对象；不制造对象树、bbox或跨物件共现。
2. 分别保存品质父范围和当前comparison_scope。父范围可能是整件物体，而CMF只看一个表面；包含关系合法，但跨对象借品质不合法。
3. ID声明当前状态single_object或有依据的ensemble；CMF声明surface或真实same_object_interface。ROI只是取景计划，实际截图还需核对。

输出：target_binding、当前scope、ROI、观察引用、scope gaps、后续品质/原生manifest准备数据。

验收与回退：缺少当前范围DNA时补查或保留未知；不改原at名称冒充覆盖。目标换了只复验受影响部分。

实际经验：前景是椅子、最终选的是旁边桌面时，不能把椅子的高级感结果直接继承给桌面。

### 09 · 当前目标的高级感流程／用途品质筛查

对应技能：[prism-target-quality](../skills/prism-target-quality/SKILL.md)

输入：原图、实际目标、分支、H01选择、范围和完整边界。

实际操作：

1. 先确认评哪个对象/哪个表面，再看设计关系是否清楚、具体、受控、可复用。品牌、价格、黑背景和“看起来贵”不能代替证据。
2. 把可读性问题与设计关系问题分开。取景能救的先裁切后核对；原细节看不见则待证；像素少但关系清楚可以评估单独展示增强。
3. 另一实际上下文复查正向证据的归属和覆盖，再让原生accept接收实际执行和审阅记录；未请求背面仅记限制，已声明关键遮挡仍阻断。

输出：admissible/FAIL/scope_pending等分明的quality bundle、父范围、实际主判/确认与引用。

验收与回退：这个“高级感”实现是设计参考用途品质，不是奢华价格或用户购买偏好预测。品质PASS不替代H2和整板。

实际经验：已冻结的全池解析实验不能因为品质筛掉一批就改变DNA成功率分母。

### 10A · ID风格第二次握手与选组

对应技能：[prism-id-moodboard](../skills/prism-id-moodboard/SKILL.md)

输入：已选语义方向、冻结ID家族、原图/实际视窗、DNA已知观察、对象绑定和quality bundles。

实际操作：

1. 原生prepare重放上游身份及规则；给模型的是当前真实材料，不是历史答案。相同字节alias消费者要贯穿全程。
2. 比较整件主轮廓、比例、体块、边界、构造主次。跨不同产品出现相似关系有价值；同功能同颜色不足以成组。
3. 在广候选中精选，完整列出未选原因。导航二次筛选必须透明，不能悄悄把100图只交给H2六七张。
4. 保留用研正反边界与未来义务，分组提案经accept_grouping后仍需实际板审。

输出：ID grouping、成员及观察证据、全部排除/待定项、当前原生状态与阻断原因。

验收与回退：原生统计通过不等于视觉正确；ID不应为了凑一致全部裁成局部纹理。

实际经验：设计师参考板里虽然跨耳机、汽车、家具，但共同的整体线面组织可读；这才是需要对齐的关系。

### 10B · CMF局部细节第二次握手与选组

对应技能：[prism-cmf-moodboard](../skills/prism-cmf-moodboard/SKILL.md)

输入：冻结CMF家族、当前surface/interface、原图/局部视窗、局部DNA、品质父范围及其绑定。

实际操作：

1. 按同一声明表面检验条件共现，或者按同一物件的真实相邻界面比较；不能用A物的颜色+B物的光泽拼条件。
2. 用可比尺度看色域、纹样、纹理、光感和分区。允许差异按家族事先说明；不机械要求每张多色，也不固定低彩度。
3. 检查第二强信号：花纹、强烈反光、交叉网格、背景或轮廓是否抢走共同主题。保留负向的原对象/程度与未来阶段，不扩大或删除。
4. 原生H2仍阻断就保留协议状态；有实际视觉试板可单列展示，不填伪义务索引把它改成原生PASS。

输出：CMF grouping、当前可消费范围、成员与反例、原生状态和未决义务。

验收与回退：父品质覆盖整件，不意味着每个CMF裁片必须展示整件所有部位。真实材料、加工、触感和反射率不由图像推断。

实际经验：最新槽纹试板第一轮的手袋有褶纹，但花色使它在组合里不一致；这是单张具备特征仍不够的真实例子。

### 11 · 合适取景与必要展示增强

对应技能：[prism-crop-enhancement](../skills/prism-crop-enhancement/SKILL.md)

输入：已声明目标、原图、ROI、原像素、比较家族和具体显示要求。

实际操作：

1. 先选最合适的取景，再谈分辨率。不能为了像素大就把无关背景放回来；不能裁掉必要反证或把ID整体变成局部。
2. 保存实际视窗并和原图核对。HTML/CSS取景保持原字节；更大截图没有新增细节。最好先找更高质量同源原图。
3. 需要AI展示增强时使用当前明确可用工具和授权，限制轮廓、纹理方向/数量、接缝、颜色和材质外观不变；另存展示版本和实际回执。
4. 复核增强是否改了设计事实。原关系证据不足不能被生成细节补齐，增强版不回灌DNA或原始品质判定。

输出：原图→comparison view→display variant链路、像素/ROI、方法与效果审阅。

验收与回退：像素不足可以补展示，但不存在的原始事实不能补造。没有可用编辑能力就明确保留原尺寸或待办。

实际经验：这一步可以插在品质/H2之前救援；只要范围变化，相关绑定和审阅也必须更新。

### 12 · 整板独立审阅与具体修复

对应技能：[prism-board-review](../skills/prism-board-review/SKILL.md)

输入：最终显示尺度的真实板、逐图原图与视窗、冻结brief、来源台账、原负向和实际选择。

实际操作：

1. 独立审阅真实图片，不让作者结论替代审美判断。逐张核当前对象、主关系、干扰、允许变化、边界和可读性，再看整板组合。
2. 程序核数量、字节与已识别项目排重；看图模型不能凭图声称验证了来源SHA。视觉、数量、语义、证据、原生门和人类反馈分别记。
3. 失败具体到图/区域/冻结条件/处理动作，优先裁切、补图、增强或从既有候选池替换。保留旧板与旧失败，只复验影响部分及组合。
4. 最多三轮同一问题定点修复，不能换编号或改阈值无限追PASS。正式H2必须经原生整板门，试板视觉PASS只能写其实际范围。

输出：board-review、每图问题/建议、当前版本状态、修复与复验链路。

验收与回退：AI独立上下文不是人类金标准；用户认可也不反写旧原生通过。

实际经验：最新单板20候选→12可继续→首版10图发现N111问题→换N080→AI视觉复核通过；没有重跑正式H01/H2。

### 贯穿 · 增量评估、协作和有界改良

对应技能：[prism-independent-evaluation-loop](../skills/prism-independent-evaluation-loop/SKILL.md)

输入：新交付、作者明确自评范围、实际依赖/输入输出与当前冻结判标。

实际经验：实跑证据与可重放代码一并交接，作者自评、机器协议、实际看图和用户意见各自保持身份。

## 如何使用这套组合

**正式新项目**：从范围约定开始，带入自己的趋势数据和用研报告；先完成纯语义H01再选向。每步按相应Skill读新材料，代码只负责冻结、验证和可重复处理。用研语义与趋势语义可独立推进，所有依赖及同一输出的修改按顺序处理。

**接续已有项目**：先核对状态和哈希，找到第一个真正未完成的依赖。已有同图R5不要重复解析；换对象就补范围绑定/品质，换一张图就补该图及整板影响，不默认重跑整库。

**只试一个新板**：可以明确为visual_trial，从已选视觉问题及已有素材开始；它可以验证选材和视觉关系，但不能伪装成新的一轮H01/H2端到端验收。最新线性槽纹案例就是这个模式。

同事第一次使用，建议先运行离线环境检查和真实案例重放，确认路径、字典、来源、图像显示与契约；随后用一张小板获得实际反馈，再由当前用户决定是否扩大。离线重放不消耗模型额度，也不产生新的准确率。

## 当前仍值得优化的环节

一级语义的粒度与独立项目容量应同步呈现；不能让设计师选完才发现只有一篇组图。选材记录应同时包含主关系和第二强信号，让花色/纹样抢主题的问题更早暴露。DNA的困难项确认应按字段类别统计收益，减少低收益调用，但先验证再改冻结规则。目标范围的身份需要从选材传到DNA、品质、H2和裁片，不让每步重新猜。最终独立视觉审阅仍必须保留，因为单张合格不保证组合一致。

上述优化中，选材前置和一次整板替换已有单板真实案例；自动粒度合并、自动选最优候选池、字段准确率和全流程无人值守都仍需新的受控验证。本包不把提案写成已实现能力。
