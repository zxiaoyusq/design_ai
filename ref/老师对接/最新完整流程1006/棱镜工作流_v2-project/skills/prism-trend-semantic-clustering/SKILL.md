# 棱镜｜趋势纯语义聚类

本版只执行用户选择的文章范围。先读 [字段与执行合同](references/format.md)。新运行使用本 Skill 自带 `scripts/semantic.py`；旧共享 `trend_text.py` 与历史输出留作原版本复放，不混用其“只统计主成员”的规则，不把旧结果改名冒充新版结果。

## 输入与共同支持

仅标题 title 和摘要 summary 进入语义判断。保留稳定 article_id、文字来源性质、日期及来源旁表；未读网页原文的模型摘要继续标 source_paraphrase。图片像素、URL、旧标签、类别、local_vl_info、图片 DNA、图像品质判断和既有聚类答案均不能进入语义请求。来源 URL 仅由程序用于同文去重，网页可以另用图片旁表预览，不影响聚类。

目标是找到多篇文章明确共同表达的审美机制，主题应兼容多个独立项目及多种视觉实现。不能用“设计、创新、可持续”等宽泛词吞并不相干语义，也不能把共同品类、同一网站或一张图的多个视角当成共同趋势。主趋势默认至少 3 个去重来源组支持；用户可调整但最低为 2。**不设 100 条或其他结果数量上限**，不为了减少数量强行合并。

显式来源组、相同规范文章 URL、精确相同的规范化标题与摘要形成去重组；未知项目/转载关系保留未知，不宣称已证明来源独立。同一网站的不同文章不自动合并，URL 的 #story 等文章身份片段必须保留。没有足够证据的主题进入候选池，单篇、单源、uncertain、unsupported 和未归类均留档。

## 分批归纳与复核

1. 冻结选择范围、文章文本哈希、Skill 版本、模型及执行时间。依实际 JSON 字符预算分包（默认 24000），不要仅固定篇数；单条超过预算显式处理，不能静默截断。
2. 各包直接阅读文字，提出主题名称、共同定义、排除边界及设计问题。每篇恰好一个主归属，无法支持则 null 并说明原因；其他独立审美机制另记次级关系，每个关系必须有本篇连续原文锚点和理由。
3. 合并目录时比较共同定义和边界，先跨包寻找语义等价项再统一 ID。目录很大可分块比对，未找到等价项就追加；禁止只对齐各包的第一批主题。合并后回查受影响关系，同一文章同一主题只能有一个关系，主归属优先，不复制次级关系增加规模。
4. 在真实全新上下文复核每条主/次关系：完整原文是否支持共同定义，是否把局部条件误写成全员属性，是否误合并。逐关系输出 supported / uncertain / unsupported 及准确引文。可以一包复核多篇，不必每篇单独调用。
5. 宿主移除模型自报的上下文 ID，依据真实执行记录注入分析、复核上下文。复核不能看到其他复核答案；不同 ID 必须对应实际不同上下文，程序只能检查 ID/哈希一致性，不能凭字符串证明独立执行。
6. 编译前检查主归属完整覆盖、次级无重复、逐关系复核覆盖和绑定哈希。文章文字、主题定义/边界或关系理由变动后，受影响复核失效；缓存只复用绑定完全一致且有真实独立执行记录的复核。

## 排序与交付

仅 supported 关系参与支持统计。每个主题按以下顺序降序排序：去重来源组数、主归属支持组数、去重文章数；相同则按稳定主题 ID 升序。主次支持合并时同文和同来源组各只计一次，同时分别展示主成员和次级成员。排序表示当前选定资料范围内的证据支持优先级，不是市场热度、增长率或商业潜力。

输出正式主题与优先级、完整候选池、主次引文、逐关系复核、来源组、未归类/不支持去向和执行记录。给下游 H01 时必须明确投影契约：主次关系不可混作互斥主成员，旧接口只能接收适配器明确定义的主成员；不得把新版 `result.json` 直接当成旧版已验收 H01 文件。

工具只冻结、验证、编译，不代替模型语义判断：
```text
python -B -X utf8 scripts/semantic.py prepare --input articles.json --out prepared
python -B -X utf8 scripts/semantic.py compile --corpus prepared/corpus.json --proposal proposal.json --reviews reviews.json --out compiled
```

修改流程后默认只做极小有代表性输入的离线验证，合成验证标 synthetic_fixture，不能宣称模型聚类质量已通过。未经当次明确请求不全量重跑，不调用历史数据规模的模型回放。
