5. 原图选择、去重与品质筛查

5.1 获取原图并建立导航页

优先复用已缓存的确切原图，否则按原记录图片URL下载。每篇最多取10个视角；超过10个时采用前7个、中间1个、末尾2个的有界采样。过滤明显头像、logo和图标URL，检查能否解码，记录来源URL、像素尺寸和SHA256。源码不把下载失败改成图像不典型。

图像按文章排成带编号的导航页。Sol先看导航页，给每篇选择一张主原图、必要时一张备选，或明确拒绝/看不清；再打开这些原图确认。导航缩略图不作为最终细节证据。

三轮累计处理1,971个图片引用槽位，1,970次成功解码；按字节去重为1,622张实际图像，来自264个不同文章ID。重复缓存与复看包含在槽位中，因此不能把1,970说成1,970张不同照片。

5.2 定义具体目标，再评品质

原图选择时写清具体范围：图中哪一件物体、哪一可见状态、哪些表面/部件；记录遮挡与未知；提出归一化取景框。ID要求当前声明状态下的整件轮廓、比例和主要结构关系，CMF允许明确局部表面或同一物件的邻接界面。不能从旁物、包装或背景借特征。

品质先于DNA运行，作为减少解析成本的筛选。原生主判逐条说明哪些证据来自选定目标，给出目标覆盖、设计参考信号、图像可用性和否决项。另一独立上下文再核对原图与目标证据，程序检查原图hash、目标身份、证据归属与输出格式。相互独立的多个目标可以在一次CLI传输内批量评估，但每项有自己的结果，不称作多次独立调用。

当前所谓“高级感”更准确是目标用途质量筛查。它检查具体、清楚、受控、可复用的设计关系；不要求昂贵、罕见、复杂、创新或极简，不测量奢华感或目标人群审美。通过只说明目标可作该用途参考，不表示与当前板一致。

5.3 去重实际做到哪里

每篇文章最多一张、同一图片SHA每板不重复是程序硬检查。最终48个板内位置对应47张独立原图/47个不同文章ID，有一个原图跨不同板复用，不违反“每板一来源一张”。

模型曾提示“可能同项目或系列”，但本轮原生source_group_id主要仍以article:ID建立；跨文章、同项目或同系列尚未形成统一且全面核实的规范身份。不能把文章级去重说成已全面完成项目级去重。

6. DNA、范围绑定与取景

6.1 Sol R5只处理品质可用的图

模型配置为gpt-6-sol、low、请求default标准档、Fast关闭；实际服务内部档位未暴露。复用相同图片字节、兼容模型/算法版本和稳定身份的旧记录；其它选中原图才做新解析。本轮47张新图执行47次主解析、40次困难字段复核，共87次DNA调用，另复用9条已有记录。

R5先读各可见分区，再整理整体形态、构造和关系。逐区检查颜色、材质外观、光泽、透明性，纹理可见时记录；保留小面积点缀和局部差异。原字典216项是词典规模，不是每张图必须填满216个值。

每张默认最多“主解析＋一次定点复核”。程序按冻结规则选择最多10个困难字段，其他未决保留pending；本轮没有开启额外refine。已知、未知、无效分开，未输出不等于没有。partial记录可以提供明确已知的局部证据，不能被改称完整解析合格。

6.2 原DNA位置与选定物件之间还有一次绑定

R5是平面位置清单，不是完整对象树或精确bbox。为防止把不同部位属性拼成一个不存在的目标，Root又调用模型看原图，将选定对象与原R5位置、观察条目一一对应。比如深色壳体与相邻金属边界，必须属于确切同一器物，不能从黑背景和旁边金属物组合而成。

ID声明单件或明确组合；一个组合有多件时，需分别覆盖其主要关系。CMF明确是一个表面还是同物件多个位置的界面关系。程序限制只能引用该图、该位置原有的已知观察，不能在绑定时新造DNA。为图像字节相同但旧新编号不同的情况，算法owner新增了精确字节别名入口，避免重复解析；Root做了8项独立边界验证。

6.3 可逆取景，不靠重新画图统一风格

实际取景采用原图归一化矩形和浏览器CSS裁切、等比例缩放；不旋转、不重绘原图。记录原图、范围、引用部位和实际显示截图。再用独立上下文看原图＋取景，确认没有截断ID主体、错用部位、看不到声明关系或因放大而丢失可读性。

另一个修复是统一“当前声明状态”。整体ID不自动等于360度、展开态或内部都可见；局部CMF也不要求整件每个面都已确认。声明内真实遮挡仍阻断，声明外未知仅限制推论。新政策用于新的实际评估，旧pending答案原样保留。此处发生了额外原生confirmation和目标复核。

这六板最终HTML使用内嵌原始图像及可逆取景，之前单独做的八张AI增强图片没有回灌DNA/品质证据，也没有被这版六板导出器自动替换进去。原生取景短边不足250像素的有6个，不足400像素的有18个；浏览器生成更大的PNG不代表获得了更多原始细节。

7. 第二次握手、整板审核与交付

7.1 实际“图片聚类”是什么

原生H2只接收明确目标、用途品质可用、DNA已知信息、原图与取景绑定一致的单位。输入还包括该方向的可见家族、必要条件、允许变化、排除项、设计师校准参考、18条原负向及未决义务。

Sol同时比较原图和当前视窗，提出成员与排除项，说明共同可见关系，引用每个成员自己的DNA观察。程序核对数量、来源身份、证据位置和负向审计。因此它实质是“在给定视觉家族下的模型视觉选组与离群剔除”，不是对全部45,000张图片做无监督聚类，也不是重新用用研图片来配图。

两个分支使用不同检查：ID比较整体轮廓、体量、构造和主次；CMF比较表面、色域、光感、纹样或同器物界面。不同品类可入同板，但仅同功能、同色、同题材或字段代码相同不足以证明一致。每个原始未知保持未知，不把不同人的相反评价互相抵消。

7.2 实际发生的整板复核

不能说六板最终版本都各自完整走过独立整板验收。程序要求组先达到内部的10张及证据门才能进入正式整板审阅；最终六板均少于10，所以最终六个版本没有六份独立正式整板通过回执。

但中间版CMF02曾达到10张，并实际做了两次整板调用，均判不一致。问题包括局部特写与整件比例混用，电子表的高对比文字、充电手柄大圆盘和密集按键改变视觉主次。随后做了范围/取景修订与重新分组，最终保留8张。第二次还修正了校准材料的传递，原失败没有被覆盖。

最终的六板由Root实际检查页面和候选图后交付为可比较候选，保留机器阻断记录。现在你认可这六张卡的视觉效果，是新的、真实的用户反馈。它不需要被旧数量门否定；同时也不伪造此前没有发生的六份模型整板PASS。

10. 建议的流程调整

以下是下一版建议，尚未在这份复盘中修改历史规则、重跑图片或偷偷升级合格状态。

优先级一：让流程符合设计决策，而不是迁就程序布尔值

  1. 把“语义方向→可见家族”设成正式模块。一个宽语义方向可有多个清楚的视觉子方向，分别写共同关系、允许变化、排除项、ID/CMF分支及参考标尺。设计师能看到并选择，不能由后台临时藏着改。语义池宽与一张板视觉收敛并不矛盾。
  2. 在昂贵解析前检查真实候选拼板。先用原图/低成本视觉摘要验证是否已有约10个不同来源能形成家族，再进入完整DNA。若只有一篇四图，在方向准备阶段就应显示素材跨度不足，而不是最终板才回头找。
  3. 拆开四种状态。语义资格、视觉一致性、证据完整性、数量充足度各自显示；设计师反馈再单列。7或8张好图不能因为未满10而完全跳过整板评审，也不能为了10强塞离群项。“约10”的具体容忍范围应作为产品政策明确，而不是Root私下加硬门。
  4. 把参考板模式与目标产品验证分开。只见当前外观并不要求补齐隐藏结构；目标产品的耐久、工艺、光泽阈值留给以后验证。原负向保留，但必须按人、原对象和当前判断维度应用。例如另一对象的亮红负评不宜自动成为所有红色ID框架的视觉阻断。

优先级二：减少重复工作，而不丢证据

  1. 按图片SHA、算法版本、目标范围缓存。同图同模型同规则DNA只做一次；ID/CMF读取各自需要的已知位置，范围变化只复核受影响部分。程序能证明的身份、哈希、引用关系不再反复要求模型回显。
  2. 缩短给每个模型的有效输入。完整原始记录存档，当前分组请求只带必要的已知事实、确切位置和相关限制；原负向仍完整保留一次，避免大量重复上下文。保留一次独立整板复核，不把每个环节都膨胀成相同材料的完整重评。
  3. 统一文章、项目、系列与图片身份。先规范source_project_id/series_id/image_sha，再选图；同项目跨文章不重复计数，未知身份单列待核，而不是靠临时标题判断。
  4. 固定取景后再解决显示分辨率。先找同源更大原图；没有更大原图时可生成单独显示增强版，但保留原始证据和增强标记，不扩大取景范围来假装清楚，也不把增强细节回灌DNA。

优先级三：让成功可以复现

  1. 把“高级感”拆成清晰的业务量表。技术可用、设计关系清楚、符合目标审美分别评。以你认可的六卡校准审美与取景尺度，同时留出新样本作检验，不能把训练参考当作新金标准确率。
  2. 重建潜力排序。库内篇数、来源多样性、时间变化、与用研的关联、可见家族素材跨度分别呈现，不用“文章多”替代潜力；预备素材不能反向排除未解析的新趋势。
  3. 将Root补救步骤变成可恢复的标准状态流。每阶段固定输入/输出和负责模块，按变更范围失效缓存。三轮上限只限制同一失败的原地重试；超限应升级方法或明确提交决策，不能自动把未完成的整个项目停下。

建议下一版顺序：两侧语义聚类 → H01与设计师选择 → 可见家族与就绪素材池 → 真实低成本预拼板 → 单图用途品质与必要DNA → 已知特征绑定/确定取景 → H2离群排除 → 最终整板评审 → 原图/增强双版本展示 → 设计师反馈回流。
