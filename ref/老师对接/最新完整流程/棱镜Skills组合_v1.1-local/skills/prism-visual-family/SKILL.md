# 语义方向到可见家族

输入已验证H01选择、完整语义边界、图片数量约定和本次校准参考。先读 [组合输入输出合同](../prism_skill_support/references/contracts.md) 的“可见家族”和 [历史与提案](../prism_skill_support/references/history-and-proposals.md)。

明确桥接：原语义问题→本次可检验设计关系→允许的跨品类参考。比如紧凑只是问题，折面叠合是其中一条探索路线；不能说前者已证明后者是用户偏好。保持原趋势主成员，扩展参考单列身份。

每家族写family_name、branch、comparison_unit、两三条关键可见条件、允许变化、排除混淆、取景尺度、校准图FileRef、原负向与未决义务。不要以功能、品类、颜色词或同参数ID单独充当风格；也不要细到一篇文章四张图才勉强匹配。

ID关注当前状态整件轮廓、比例和结构主次；CMF关注指定表面、色域、纹样/光感或同物件相邻界面。整板多彩不要求每张同时多色；未请求的背面/展开状态不自动成为缺陷。

同事可用 [六卡校准材料](../prism_skill_support/assets/calibration/README.md)，这些是已获正面反馈的历史参考，不是新候选图或独立金标。新任务有用户参考时以当前明确要求为准。

记录本次策略由谁选择、怎样来自H01，以及素材不足的风险。原流程需要Root反复回找，这个动作在本Skill中显式留档，不冒充固定机器自动聚类。若选择预DNA真实预拼板，标记为提案版试验，不把未做过的门写成已验证。

输出visual-family.json及native-brief准备数据，交给选图；先冻结条件，再看结果，不能为收够数量逐图改预期。
