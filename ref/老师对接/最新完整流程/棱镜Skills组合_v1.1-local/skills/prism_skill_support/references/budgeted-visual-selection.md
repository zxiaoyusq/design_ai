# 基于已有 DNA 的省额度选图政策（本地维护版）

这是 v1.1-local 的执行编排政策，适用于当前项目选择使用已有图片 DNA、已有语义召回与真实历史回执来减少重复看图的任务。它不修改原始 v1.0 压缩包、冻结运行、原生品质/绑定/H2 合同或模型原回答，也不代表该策略已通过新的真实视觉实验。本文是本套件预算规则的唯一维护位置。

## 授权与暂停边界

实施 Skill、离线准备和恢复执行是三件事。先继承当前项目的授权、暂停点与调用开关；修改这些文档或准备代表图不会开启模型执行。用户要求“全库文本结束后暂停”时，只整理已产生的文本结果、准备本地候选与预算计划并停在该检查点；不得自动启动原图、品质、ROI、分组、整板模型调用或失败图修复。已有恢复授权仍可复用，但明确暂停不能由计时、脚本重启或新目录解除。

不默认让供应商重新阅读已有 DNA、文章或语义结果，也不为本地预分组启动供应商 embedding、摘要或筛选请求。原图阶段实际执行时沿用项目已选模型与 DeepAgents 调用入口，保存模型版本、prompt、时间及真实回执；不能把模型更换写成历史执行事实。

## 本地预分组、去重与代表图

1. 保留全库覆盖台账及各方向全部候选；失败、未决、尚未处理不是“无匹配”。预分组与排序只组织后续阅读次序，不改原语义归属、原 family、原负向或原 DNA。
2. 在每个方向内，按当前 family 的 `primary_questions`、比较单位和同一目标/位置上的**已知可见关系**整理候选小组。例如“连续主体浅色面”与“仅背景浅色”分开；CMF 的同表面/同物件界面与 ID 的完整轮廓保持各自范围。同颜色、同题材、同品类不能独立成为视觉一致的结论。
3. 使用原 DNA 的可用观察索引、位置和原值；保留 pending、invalid 及其冲突，不将它们充作正证据。每个本地小组记录方向、关系依据、原索引、目标范围、限制、成员及代表/未选原因，标记 `local_preselection_only`。缺事实的候选仍留在待核队列，不自动补造新的多模态事实。
4. 按原图 SHA256 去除完全相同的字节重复，保留全部原始来源别名。项目/系列或近似图片去重必须有已有证据；未知来源不能因名称相似被合并，也不能凭程序预分组断言图片视觉重复。每篇文章的正式主图政策、独立来源门继续有效，备选不销毁。
5. 优先选择与冻结可见关系匹配、目标位置明确、支持所需关系的证据完整的代表；再用历史品质作为次级参考，并兼顾真实来源的代表性。历史品质 PASS 不自动授予当前目标 PASS。分辨率、文件尺寸或压缩格式不得替代审美/品质排序；技术上打不开或无法辨识时单列技术缺口。
6. 代表没有占满所有关系组，不等于其他组已被视觉否定；记录剩余候选与改选入口。提出的新 family 与冻结 family 分开保存，未经实际范围裁决不得混入同板。

## 累计预算与阶段推进

下面是**本次项目的可配置预算**，不是对所有项目固化的默认数量或最低执行量。以项目 `visual-budget-policy.json` 的当前授权版本为准；用户只要少量成果时按其范围选择少量代表，不为了用满额度补跑。数量/证据门与预算分开，预算不足不允许降低成板门槛。

| 环节 | 预算边界 | 推进和停止规则 |
|---|---|---|
| 每方向原图阶段 | 累计不同原图 **24 → 40 → 60** 张 | 先在 24 张累计额度内覆盖代表关系。仍缺支持冻结条件的候选，且存在有据的未看代表，才在当前执行授权内登记扩到 40，再到 60；分别只增加 16、20 张空间。无新有据候选时不为用满上限调用。 |
| 每方向详细 ROI 入围 | 累计不同原图最多 **12** 张 | 从已看原图中选最相关且证据充分者进入详细绑定/实际视窗复核；换入另一原图占一个新名额。相同图改 ROI 保留原选择及修订引用，并计重复提交，不能借修订无限新增入围图。 |
| 每块板的独立整板审阅 | 最多 **2** 次真实模型请求 | 第一次独立看真实整板＋成员原图/实际 ROI；若有具体可修的真实意见，第二次核修订后的实际版。更换文件名、board_id 或小幅重排不重置同一方向同一板任务的额度。 |
| 每方向视觉请求总量 | 累计 **120** 次 | 所有视觉阶段合计，包含继承的真实成功、失败、未知请求及在途预留；不能分阶段、换run或换模型重置。 |
| 每方向图片附件总量 | 累计 **240** 个附件出现次数 | 原图、ROI、校准图和整板的每次附送均计；重复原图依然占附件量，继承历史投入和在途预留。 |

累计从该方向已有真实记录开始，包括继承/复用运行中确实看过的原图，不按批次、轮次、分支目录或新 run 清零。按 SHA 去重核算不同原图；同图重复调用虽不新增原图数，仍消耗提交/请求/token。发送新原图前预留名额，已实际发出的失败请求保留投入记录，不能以未产出 PASS 为由释放预算再无限发送。确认从未发送的准备项单列，不计真实调用。并发时预留与提交共用同一账本，防止同时越界。已有历史累计超过新上限时，剩余额度为零，明确披露历史投入；不删除旧成果、不篡改旧账，也不宣称历史执行符合新预算。

视觉请求和附件上限是双重消耗约束，不承诺固定Token值；任何一项先达到都不能继续新增请求。真实 tokens 另计，未知项单列。使用项目并发原子预算 guard 做提交前预留与落账，并尊重项目为最终审阅登记的保留额度；不能绕过guard直接请求供应商，也不能把同一调用的已发记录和预留重复相加。

本次已有整板历史：H006、H012各有3次，H013有2次。保留这些真实记录；未通过不赋予新的审阅额度，不能因换成维护版或新目录再发一次。具体历史数以实际回执重放为准，不能把此项目的计数继承为其他项目历史。

预算上限不是自动执行许可。明确暂停时，不得为了升到下一档、修复视窗或第二次审板而继续供应商请求。原有“同问题最多三轮修订”等通用建议也不能越过这里更具体的原图、ROI、整板或当前暂停边界。

达到某项上限，停止新增该项消耗；已具备真实证据的候选可在其他预算余额内组板和验收。整板预算到限且未通过，或所有合法推进阶段无余额时，停止该方向新增探索，保留缺口。例：原图累计60张或详细ROI累计12张到限，不禁止使用既有合法6图完成仍有额度的独立整板审阅；整板2次已用完且仍pending，则停止新增原图探索。中央预算guard按各指标新增消耗原子核验，阶段推进同时遵守收尾规则和项目暂停。记录 `budget_reached` 及具体耗尽项；需要新预算才能继续时，本项目可继续性状态为 `awaiting_user_budget_decision`，附已取得结果、未成板原因、剩余候选和下一接续点。真实已通过的方向保留通过依据；缺证、数量不足或视觉未决仍按原状态展示。不能宣称候选已耗尽、所有组合均无效或整个项目已完成。其他方向仅在仍有当前授权和余额时可继续；项目级暂停优先。

## 必须保留的真实判断

本地小组和代表图只构成候选。正式成员仍须遵守实际原图目标选择、当前目标品质、原 DNA 绑定、独立实际 ROI 复核，以及独立实际整板判断。ROI 要用真实展示视窗并与原图对应；ID 的关键整体关系、CMF 的选定同表面/界面都不能由文本评分代替。最终显示发生影响审阅的变化时，保留待核或用剩余额度重审，不能沿用不对应像素的旧 PASS。

本次只把“首次 target 与 quality 合并请求”记作**待验证优化**，不要求现有执行链立即合并，不减少独立 ROI 或整板门。将来若试验，须单独记录合同版本、输出的两个判断和验证范围，不能伪称已经降低实际调用量。

联系表/多图拼图是可选阅读方式，**默认不启用**；它需要另行明确采用并验证识别粒度、源图回链和预算口径。联系表不能替代原图、详细 ROI 或最终整板的独立审阅，也不能把一张拼图中的多张原图计为一个独立素材。

## 分开记账与交付

至少分别记录以下实际指标及其来源，不把“张数”当成请求数：

- 不同原图：方向内累计已看 SHA 并集、历史复用数、已提交/预留但尚无成功阅读的 SHA；同时保留跨方向去重的全项目数量。
- 图片提交：原图、实际 ROI、校准图、整板分别计出现次数；同一图片重复附给不同请求，每次均计提交。
- 真实请求：实际供应商请求及成功/失败/取消状态；DeepAgents 如产生多个内部请求，按真实回执计数。准备、程序重放和本地浏览不混入供应商请求。
- 使用量：实际 input/output/cache token 分列；未知记未知，不作 0，不把缓存项再次叠加为总输入，也不凭 token 推算已支付费用。
- 预算状态：当前累计档位、各阶段已用/预留/剩余、扩档依据、暂停/到限原因及未解决问题。预算策略改变另存版本，旧账不重置。

交付仍分 semantic、visual、quantity、evidence、user_feedback 五种状态，附本地预选与真实模型判断的区别、原图/ROI/整板哈希及回执。原 ENJOY 只证明该用户整图偏好，不升级为逐特征喜欢；研究参照不计正式趋势主板数。
