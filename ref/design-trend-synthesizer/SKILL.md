# 通用设计趋势归纳

找出趋势与用研在审美、材料、形态、触感、情绪或使用场景上的明显重合，归纳成设计启发。相近的诉求与表现就可以提出方向，不要求证明严格一致的机制；跨品类做法用“可探索”表述。

**默认3.3轻量流程：日期筛选 → 按 clustering_label 聚合同类文章 → 单一主题的趋势与共享用研笔记 → 按大类综合出稿。** 小资料保留分组，直接一次出稿。删除逐条观察提取、主题排他分配、候选独立筛选、分轮合并、全量反证、逐卡撰写与审核。中间不使用2.x证据契约，不为格式纠错追加模型调用。

## 准备

确定输入、项目根目录和明确起止日。“最近两个月”按当前日历日期解释，不按资料最大日期推算。release_time只筛趋势，起止日都包含；用户文本不按趋势日期筛选。`--user-limit N`选择原users数组前N个完整对象。

```bash
python SKILL_DIR/scripts/pipeline.py prepare \
  --trends PROJECT/data/trend_data/article_table_2/trends.json \
  --users PROJECT/data/userreseach_data/users_selected_5.json \
  --project-root PROJECT \
  --start-date YYYY-MM-DD --end-date YYYY-MM-DD --dry-run
```

默认来源是上述新版趋势和五用户文件；可用 --trends/--users 指定其他 JSON，不读取实时数据库。准备返回大分类及文章数、计划调用数、消息字符数及输出预算。范围符合已有任务后去掉`--dry-run`执行，使用返回的run_dir。默认保存到`data/result/high_trend/<run_id>/`，不覆盖旧结果。

- clustering_label 是已有大分类，不作为模型重新聚类的任务。同类文章先按标签归组（包括原文件中不相邻的文章），不同大类不混入趋势归纳包；类内过长才拆包，最终把同类的所有笔记共同考虑。缺少/空白标签放入“未分类”，不猜标签。
- 每包完整消息默认最多48,000字符，允许跨用户合包。问题/场景与画像在包内去重，回答全文保留。用研只归纳一次，各大类共享这些笔记，不按类别复制完整用研；后续只读方向笔记，不重复发送问答。
- 默认总调用上限24次，包含失败重试；分包归纳与最后成稿默认不传 `max_tokens`，不设置应用层输出上限，模型服务或 SDK 的默认限制仍可能生效。字符不是token。超过计划调用预算时在调用前停下，不自动扩大预算。
- 缺少双侧资料时输出空范围说明，不调用模型。空回答和“未提及”问答由代码过滤，无归属需求不参与用户统计。

## 执行

有适配器时让脚本自动推进，不让宿主逐批读取原文、反复协调或创建大量子Agent。准备时用`--model`及`--model-parameters`声明实际配置，按[轻量执行说明](references/lean-workflow.md)运行。Skill仅依赖Python标准库，不绑定模型服务。

没有适配器时用宿主模型：

1. `pipeline.py next --run RUN`返回待处理请求；读取`RUN/requests/<job_id>.json`中的messages，在短上下文中处理这一包。
2. 回复保存为普通Markdown，执行`pipeline.py accept --run RUN --job JOB_ID --response REPLY.md --model 实际模型`。
3. 继续next，代码在笔记齐备后只生成一次综合任务，并编译最终文件。

趋势包结合本大类文章提炼共同表现与细分机会，用研包整理用户诉求与偏好。每条笔记只回答一个具体设计问题，标题、归纳与来源围绕同一核心；每包约6–12条仅为篇幅参考，不能为凑数或压缩数量混合主题。不逐条生成观察、引文、跳过原因或覆盖清单。不同偏好自然保留在简短条件中，不展开反证。

综合时，只合并能共同回答同一具体设计问题的表现。同属大类或都与“个性表达、情绪价值、生活方式”相关，不足以合并。例如“传统图案几何化”可与“局部几何装饰偏好”形成方向；“图案怎么表达”和“部件能否更换”应分别整理。同一来源可以支持多个方向，不做排他分配。旧笔记混合主题且无法细分引用时，仅作背景，不用它补齐双侧关联。

每卡先简述实际交集，再用“可探索”提出建议；标题围绕交集，不把延伸做法当成原文事实。用研只谈几何时，不因趋势具有文化背景就宣称用户认可该文化。无明显交集不凑数，用研可支持多个类别。

**趋势命名：** 中间笔记、主方向和用研补充均采用概念型、名词性名称，风格参考“可持续材料与再生美学”“灵活适应性建筑思维”。以核心设计主题及其特征命名，简洁且能区分细分方向；不照搬大类名称，也不为显得宏观而扩大来源含义。避免“让……”“把……”“先……再……”等建议句、口号或收益承诺，具体做法放在正文。按语义选用“美学、语言、思维”等词，不机械添加后缀。原 clustering_label 保持不变。

- “让循环材料先以细腻质感赢得接受” → “循环材料与精致触感美学”。
- “把图案转译为克制的几何细节” → “几何转译与局部装饰美学”。
- “保留稳定主体，让外观表层可以更换” → “可替换表层与适应性外观”。

**普通文字即可。** 综合报告使用`# 大趋势分类：原标签`及其下的`## 新方向标题`和`[T00001 U000001]`，综合阶段引用代码提供的`[N0001 N0015]`。不要求JSON、固定字段或每条资料恰好分配一次。缺标题、围栏、未知编号等由代码整理；未知编号不关联，保留正文并提示，不让模型重写。输出截断保留现有内容并标注，不自动续写。

正文只引用直接支持核心交集的来源。可选背景另起一行`背景参考：说明 [N0008]`，没有就不写。代码将其放入 background_source_records，仅供查阅，不参与主方向双侧判断、用户人数、分类或图库；未标注的旧引用仍按核心处理，不靠关键词猜测主题或自动拆卡。具体编译口径见[轻量执行说明](references/lean-workflow.md)。

模型只写归纳和编号。代码根据实际引用的趋势来源恢复 clustering_labels，不相信模型自造类别；跨类方向只写一次并保留多个类别归属。JSON 的 trend_categories 保留每类文章数量与结果索引，包括无主方向的类别；trends 中每张卡保留 clustering_labels。代码生成JSON/JSONL/Markdown、来源定位、引用用户去重和图片路径。原文单独保存为sources.json，不逐卡重复嵌入。综合请求只发短笔记；摘要被限长时记录提示，完整笔记仍保留，不声称逐条观点全部覆盖。

## 交付

- 主方向有趋势与用户来源关联即可，不加评分门槛或独立审核。个人偏好不写成市场共识，题干不当回答，原型不改成已验证量产能力。
- `# 用研补充`以用户议题为主，引用用户去重超过分母一半才称“多数提及”，含不同态度，不是偏好率。不要求逐趋势反证表，未覆盖仅为已读摘要判断。其余线索留在诊断中，不输出未入选文章清单。
- 只使用文本，不读图片、不访问输入URL。用户图片仅关联明确标记为 `LIKE` 或 `ENJOY` 的记录：图片偏好还须在回答中实际提及图号；问答和需求的正向 `ref_pic_links.local_paths` 是显式关联，即使正文没重复图号也可保留。`DISLIKE`、`REFERENCE` 和未标注图片不进入结果图片、图片清单或网页图库；它们所在回答的文字仍可用于归纳差异和边界。
- 代码汇总、去重全部已选用户中明确 `LIKE` / `ENJOY` 的本地路径，并保留用户和来源定位。未关联方向的喜欢图片只能作为资料入口，不能冒充某个结论的证据。文件缺失保留声明路径与缺失标记，不伪造可用图片。主卡仅关联核心来源的图片；趋势配图按来源文章组织，背景引用不带入主卡图库。文章关联不代表每张配图与结论视觉一致，也不代表用户认可。
- 不输出“下一轮验证”。缺少来源或批次失败时如实标明范围，不因格式问题阻断全部材料；没有正文则标为空。
- 交付report.md、image_paths.md、high_potential_trends.json和performance_report.json的真实链接。image_paths.md展示趋势文章图片，以及结果关联和其他明确 `LIKE` / `ENJOY` 的用户图片；用户侧各部分按规范化绝对路径去重，不展示 `DISLIKE` 图片。JSON 以 `user_image_filter: like_or_enjoy` 声明口径，report.md 提供查看入口。只做一次简要内容检查，不再启动审核轮。用量取日志，缺失值保持未知，宿主对话与后端调用分开。

## 验证与旧运行

**流程验证默认只用极少量代表样本**：例如1–2条趋势、2–3位用户、约5–8条长短及不同态度的回答，优先假适配器。没有用户明确要求，不跑全量、前20用户或超大输入模型回放。小样本不能证明全量效果或实测节省比例。

新增测试：`python -m unittest discover -s SKILL_DIR/tests -p 'test_lean_*.py'`，全部为微型离线夹具，无真实模型调用。

2.x文件仅保留供历史运行续跑，入口按旧manifest自动识别；新prepare默认3.3。确需处理历史流程才读[旧版说明](references/legacy-v2.md)或使用旧分发包。不要为新任务加载旧契约或恢复旧八阶段队列。
