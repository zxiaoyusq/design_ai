# 通用设计趋势归纳

找出趋势与用研在审美、材料、形态、触感、情绪或使用场景上的明显重合，归纳成设计启发。相近的诉求与表现就可以提出方向，不要求证明严格一致的机制；跨品类做法用“可探索”表述。

**默认3.0轻量流程：代码整理 → 几包方向笔记 → 一次综合出稿。** 小资料直接一次出稿。删除逐条观察提取、主题排他分配、候选独立筛选、分轮合并、全量反证、逐卡撰写与审核。中间不使用2.x证据契约，不为格式纠错追加模型调用。

## 准备

确定输入、项目根目录和明确起止日。“最近两个月”按当前日历日期解释，不按资料最大日期推算。release_time只筛趋势，起止日都包含；用户文本不按趋势日期筛选。`--user-limit N`选择原users数组前N个完整对象。

```bash
python SKILL_DIR/scripts/pipeline.py prepare \
  --trends PROJECT/data/trend_data/trends.json \
  --users PROJECT/data/userreseach_data/users.json \
  --project-root PROJECT \
  --start-date YYYY-MM-DD --end-date YYYY-MM-DD --dry-run
```

准备返回计划调用数、消息字符数及输出预算。范围符合已有任务后去掉`--dry-run`执行，使用返回的run_dir。默认保存到`data/result/high_trend/<run_id>/`，不覆盖旧结果。

- 每包完整消息默认最多48,000字符，允许跨用户合包。问题/场景与画像在包内去重，回答全文保留；后续只读方向笔记，不重复发送问答。
- 默认总调用上限24次，包含失败重试；分包归纳与最后成稿默认不传 `max_tokens`，不设置应用层输出上限，模型服务或 SDK 的默认限制仍可能生效。字符不是token。超过计划调用预算时在调用前停下，不自动扩大预算。
- 缺少双侧资料时输出空范围说明，不调用模型。空回答和“未提及”问答由代码过滤，无归属需求不参与用户统计。

## 执行

有适配器时让脚本自动推进，不让宿主逐批读取原文、反复协调或创建大量子Agent。准备时用`--model`及`--model-parameters`声明实际配置，按[轻量执行说明](references/lean-workflow.md)运行。Skill仅依赖Python标准库，不绑定模型服务。

没有适配器时用宿主模型：

1. `pipeline.py next --run RUN`返回待处理请求；读取`RUN/requests/<job_id>.json`中的messages，在短上下文中处理这一包。
2. 回复保存为普通Markdown，执行`pipeline.py accept --run RUN --job JOB_ID --response REPLY.md --model 实际模型`。
3. 继续next，代码在笔记齐备后只生成一次综合任务，并编译最终文件。

每包只写约6–12个设计方向及少量来源编号，不逐条生成观察、引文、跳过原因或覆盖清单。不同偏好自然保留在简短条件中，不展开反证。最终一次生成多个方向，不刻意压成两张，也不凑数量。

**普通文字即可。** 推荐`## 方向标题`和`[T00001 U000001]`，综合阶段引用代码提供的`[N0001 N0015]`。不要求JSON、固定字段或每条资料恰好分配一次。缺标题、围栏、未知编号等由代码整理；未知编号不关联，保留正文并提示，不让模型重写。输出截断保留现有内容并标注，不自动续写。

模型只写归纳和编号。代码生成JSON/JSONL/Markdown、来源定位、引用用户去重和图片路径。原文单独保存为sources.json，不逐卡重复嵌入。综合请求只发短笔记；摘要被限长时记录提示，完整笔记仍保留，不声称逐条观点全部覆盖。

## 交付

- 主方向有趋势与用户来源关联即可，不加评分门槛或独立审核。个人偏好不写成市场共识，题干不当回答，原型不改成已验证量产能力。
- `# 用研补充`以用户议题为主，引用用户去重超过分母一半才称“多数提及”，含不同态度，不是偏好率。不要求逐趋势反证表，未覆盖仅为已读摘要判断。其余线索留在诊断中，不输出未入选文章清单。
- 只使用文本，不读图片、不访问输入URL。代码关联已有图片路径，缺图留空；文章图片不代表视觉核验或用户认可。
- 不输出“下一轮验证”。缺少来源或批次失败时如实标明范围，不因格式问题阻断全部材料；没有正文则标为空。
- 交付report.md、image_paths.md、high_potential_trends.json和performance_report.json的真实链接。image_paths.md分为结果关联图片路径，以及与前者去重后的全部用户提及图片路径；两部分内部也按规范化绝对路径去重。只做一次简要内容检查，不再启动审核轮。用量取日志，缺失值保持未知，宿主对话与后端调用分开。

## 验证与旧运行

**流程验证默认只用极少量代表样本**：例如1–2条趋势、2–3位用户、约5–8条长短及不同态度的回答，优先假适配器。没有用户明确要求，不跑全量、前20用户或超大输入模型回放。小样本不能证明全量效果或实测节省比例。

新增测试：`python -m unittest discover -s SKILL_DIR/tests -p 'test_lean_*.py'`，全部为微型离线夹具，无真实模型调用。

2.x文件仅保留供历史运行续跑，入口按旧manifest自动识别；新prepare默认3.0。确需处理历史流程才读[旧版说明](references/legacy-v2.md)或使用旧分发包。不要为新任务加载旧契约或恢复旧八阶段队列。
