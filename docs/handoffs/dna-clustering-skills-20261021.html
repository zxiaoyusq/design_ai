2. 两步怎么衔接

A：先完成当次图片清单的设计卡准备

输入包括图片清单、原图路径与 SHA256、已有 R5／旧观察及来源。A 选取主物品或同级、具有独立设计表达的对象，保存对象框、事实框和展示框；三个框均为原图归一化 [x, y, width, height]。整体与代表性局部均可，图片中的细小背景碎片不应成为凑相似的依据。

每个对象记录配色、廓形、块面、线条、光学、纹理和构造细节，以及支持证据、未知项、竞争焦点和可读性限制；再提取同层风格候选与单图设计情绪。当前紧凑预算每图最多 1 张 ID 卡、2 张 CMF 卡。全部输入有成功／失败终态并冻结后，再交给 B。

B：先比较 DNA，再看真实图片选员

  1. 文字发现：默认每批最多 32 张设计卡，让大模型归纳有依据的共同关系及边界。
  2. 跨批归并与召回：比较各批提出的关系及代表卡，把所有相关批次的卡路由到合适方向；后续批次的图片可以加入先前发现的方向。
  3. 文字提名：从方向内的卡中提名视觉候选。预算会限制进入实际看图阶段的数量，未入选不等于素材没有价值。
  4. 真实看图：默认每窗 16 个候选，比较原图与按冻结框生成的真实裁片。先明确共同关系和破坏条件，再逐个判断差异是否协调，最后组成板；多窗结果作有界合流。

32 是文字请求容量，不是一个板的来源边界。当前默认统一按设计情绪比较，ID／CMF 仅保留为原卡的事实出处；新组使用 DESIGN。聚类阶段不补写 DNA，也不临时换框。

已有 DNA 是否需要重跑

现状处理
已有可追溯的冻结设计卡，事实足够直接将 prepared-manifest.json 交给 B；无需先再跑 A。
只有旧 R5，缺少当前所需的关系或取景由 A 复用 R5 的事实，补明确缺项；保留旧结果。
新一轮 A 希望复用旧设计卡显式传 --reuse-prepared。会核对原图、路径、对象／视窗、实际 Prompt／Schema／模型和原始证据，不是仅凭文件名或 SHA 命中。
DNA 已写出冲突，组板仍把图片放在一起这是 B 的关系判断问题，针对该组合重选或扩充候选。
原图细节可读，但板上显示太小调整展示布局；原图本身看不清的细节，放大无法补出证据。

历史 v1 卡可在核验后供 B 消费，但不等于已按 A 的 v2 Prompt 补齐。把旧全量图片清单重新传给新版 A，可能产生大量未命中请求；应先确定实际缺口。

3. 当前成板标准

  • 整体设计情绪一致：配色角色、廓形比例、块面、线条、光学、纹理和细节组合后，应指向相近感受。不能仅凭“都是黑色”“都有圆角”或“都是金属”入板。
  • 跨品类、跨材质允许：服装、家具、汽车、电子产品和空间可以同板；各维度可以变化，变化要协调。现代服装的肩线、剪裁、分片也可形成结构化廓形。
  • 有设计表达且关系成立：优先比例、构造、色面和细节组织清楚的图片。单图有设计感，不自动证明与其他图协调。
  • 同品类最多 50%：按对象功能归一，每板同类最多 floor(N/2) 张。不同椅子仍属椅子，不同房间整体装修仍属室内空间；未知不当新品类。
  • 默认 6–10 张，目标 8 张：不足保留小组，不为凑数接纳明显离群项。此前某轮“每板至少 5 张、最多两小时”是该轮约定，没有改写当前 Skill 的默认规则。
  • 保留真实取景和证据限制：局部可以进板，但应代表物品的设计关系；不能裁掉冲突，也不能借背景或光晕替产品描述材质。
  • 核对最不一致成员对：A 接近 B、B 接近 C，并不自动证明 A 与 C 可以同板。主导冲突或未决成员不能靠宽泛标题保住名额。
  • 来源与反馈：每文章／已知项目最多一张，秀场最多 floor(0.3×N)；未知保留未核。具体反馈绑定对象、视窗和原组合，换目录或板名不会消除问题。

规则详见 统一生产判断、规模化聚类及 定点修订。

4. 接手与运行入口

保留包内目录层级，在解压后的项目根目录执行。脚本按相对位置查找两个 Skill、风格库与传输依赖；只拷贝两个 SKILL.md 不能运行完整脚本。接收方需准备 Linux／WSL 环境、Python 3.14（本项目为 conda 314）、Python 依赖，以及脚本兼容的模型执行与登录环境。

requirements-runtime.txt 与 runtime-versions.json 记录打包时当前环境的直接依赖版本。源码中模型配置为 gpt-6.1-sol / high，实际请求通过 DeepAgents 和现有 CLI 适配器执行；能否在接收环境使用须由该环境核实。包内没有账号凭证、第三方安装包或模型程序。

先核验文件与查看参数

python verify_package.py
python .agents/skills/prism-design-dna-preparation/scripts/design_cards.py --help
python .agents/skills/prism-dna-cluster-moodboard/scripts/llm_group.py --help

A：仅生成准备计划的示例

python .agents/skills/prism-design-dna-preparation/scripts/design_cards.py \
  --sample /absolute/path/sample.json \
  --prior-observations /absolute/path/prior-observations.json \
  --out /absolute/path/new-preparation \
  --batch-size 1 --workers 10

sample.json 的 images 条目需包含唯一 image_id、sha256、真实 local_path，并沿用已有来源和 DNA 引用。已有冻结卡直接走 B；A 的跨运行复用另加 --reuse-prepared /absolute/path/old/prepared-manifest.json。输入范式可对照包内 既有测试夹具，其中假数据仅解释协议。

B：优先少量板的计划示例

python .agents/skills/prism-dna-cluster-moodboard/scripts/llm_group.py \
  --prepared /absolute/path/preparation/prepared-manifest.json \
  --out /absolute/path/new-grouping \
  --comparison-mode unified --mode priority_boards \
  --target-boards 3 --direction-limit 4 \
  --workers 10 --card-batch-size 32 --visual-batch-size 16 \
  --max-calls 30

示例中的方向数、调用预算和并发需要按本次任务约定设置，30 次不保证能产出三张达标板。两个入口默认显示计划，追加 --execute 才启动真实调用；已有具体反馈时为 B 追加 --feedback /absolute/path/registry.json。全目录探索使用 --mode full_catalogue，并去掉仅用于优先模式的板数和方向数参数。

跨批复用旧方向可用 --templates-from；同计划接续使用 --resume，只复用身份一致的真实成功回执，失败不会自动重发。当前无自动额度兑换或购买。调用预算与墙钟时限不同，主入口没有通用“两小时结束”的命令行开关，需要运行调度另行落实。

展示与修订

render_delivery.py 将已有输入、观察、分组和板数据编成离线页面；需要通过参数绑定相应文件。capture_boards.cjs 是可选浏览器截图工具，需要 Node.js、Playwright 和 Chromium。revise_llm_boards.py 处理有明确问题的事实、关系或显示修订，详细协议见上述定点修订说明。

目录中 freeze_prepared.py、observe_sample.py、cluster_sample.py 等旧脚本为历史兼容保留。当前主流程入口是 design_cards.py → llm_group.py；不要把旧代码距离聚类当作现行大模型聚类。

5. 四张参考图例与反馈教材

四张原板用于教学和明确要求的效果对照。迁移的是“事实如何形成共同设计关系”的判断方法；参考板的颜色、材质、物品类型和版式不应变成全局偏好。当前生产请求不自动附带这些教材图片。

完整图例教学 · 反馈案例解析 · 三板问题圈注原件

历史反馈集中在：次要共同点掩盖主导差异；把无纹样当成形态简单；忽略背景、光晕或文字的竞争影响；把微纹理和宏观起伏等同；放大了低清局部却没有补出证据。未圈注不等于通过，反馈也不是永久图片黑名单。

6. 迁移范围与已知边界

  • 本包包含两个主 Skill 的全部有效源文件及现有测试、风格参考依赖、传输适配源码、四张教材原图和问题圈注 HTML；不含 1600 张原图库、全量 DNA、历史执行回执、账号、密钥或运行中的服务。
  • 复用历史结果需另外携带原图及被引用的样本、旧 DNA、原请求／回答／回执。只拿 prepared-manifest.json 或一份设计卡 JSON 通常不够。
  • 现有冻结证据使用绝对路径并绑定 SHA。跨服务器迁移时须保留可解析的来源路径，或另行设计可追溯的迁移映射；简单改 JSON 路径可能破坏证据链。本包没有自动迁移历史运行的功能。
  • 历史脚本和文档中的 data/result/… 路径是原项目档案引用，未随包携带；可选旧流程依赖并不等于当前两个入口的运行必需项。
  • 版本更新、结构校验成功、DNA 可消费、图片选组、正式整板验收与设计师批准分别记录。现有规则仍可能出现错误组合，目标板数不构成质量保证。
  • 打包只做文件完整性、链接和入口加载核验，没有执行新的 DNA 提取或图片聚类任务。

文件来源与 SHA 见 manifest.json。解压后运行 python verify_package.py，可离线检查所有已登记文件的大小与 SHA256。
