# 架构决策

## 2026-09-02：局部修复只修改精简观察，失败时保留原始问题

- 编译器同时记录扁平语义校验路径和最终模块/元素 Schema 路径，二者都必须指向原始 `design_observations`、`uncertainties`、风格或证据 JSON Pointer；模型补丁不得直接修改编译后的 `design_elements`。
- 修复响应无法解析或 JSON Pointer 不存在属于补丁执行失败，不得覆盖触发修复的原始校验问题。系统记录补丁错误后继续使用原始源路径执行保守整理。
- 推断字段证据不足时可以请求模型从已有证据中做一次局部补证，但不得由宿主生成证据；补证失败且观察置信度不足时移除该观察，其他已闭环结果继续保存。

## 2026-09-02：有效证据区域由宿主同步到主体声明

- 证据框相对主体框每边不超过 0.05 的差异视为坐标取整偏差，宿主可把主体框扩至证据边界；任一边超过容差时不得自动扩大。
- 当证据已经包含非空区域、有效归一化坐标和可见描述，但 `target_object.visible_regions` 漏登记同名区域时，宿主编译器补入该已有区域；这属于重复声明同步，不需要模型重新判断图片。
- 编译器不得根据字段 ID、风格名称或描述推导不存在的区域。证据记录不完整、坐标无效或字段使用了无证据支持的区域时，仍保留为语义错误。
- 每条最终证据保留到模型观察 `/evidence/<index>` 的源路径映射，便于局部诊断；最终校验器仍独立检查区域闭环，不能因同步逻辑放宽其他证据规则。

## 2026-09-02：提取过程通过任务快照展示受控阶段事件

- 继续复用现有后台任务与前端轮询，不为当前进程内任务额外引入 WebSocket、SSE 或消息队列；每张图片保存稳定阶段、估算进度和最近 80 条事件，批量任务进度取各图片阶段进度的平均值。
- 阶段事件覆盖准备、模型请求开始/完成/异常、解析、确定性编译、风格语义复核、局部修复、最终校验、业务视图和追溯保存；事件回调属于旁路能力，记录失败不能中断提取主流程。
- 页面只展示由应用代码生成的状态文案和请求计数，不展示模型隐藏推理、原始思维过程、密钥或完整请求内容。阶段百分比明确标记为估算值，不冒充模型内部的精确完成度。
- 远程网关超时与结构/语义校验失败分开提示，避免把尚未生成完整模型结果的 524 等网络错误描述为“最终检查失败”。

## 2026-09-02：风格证据由宿主值级挂接，歧义项使用窄范围语义复核

- confirmed 主模型观察不再必须维护规则计数及 `core_feature_hits` / `auxiliary_feature_hits`；主模型集中输出图片事实、规范字段值和风格判断，宿主把 confirmed 状态展开为最小规则覆盖，并在最终保存前重新执行完整硬规则校验。
- 新增宿主专用 `style-evidence-rules.json`。只有明确的受控枚举、数值阈值或跨字段组合条件命中时才能自动挂接风格证据；字段 ID 位于风格 allowlist 只代表“允许使用”，不能把任意字段值直接解释为支持。
- 无安全值级规则但存在置信度不低于 0.75 的允许字段时，编译器生成最多 3 个风格、每角色最多 6 个字段的复核请求。复核使用独立 DeepAgent，仅传入相关知识库段落、字段值、描述和证据引用，不传图片、完整 Skill 或完整注册表。
- 语义复核按角色选择一个字段或最小字段组合；core 组合至少包含一个 `decision_use=hard` 字段。只有复核置信度不低于 0.75 的正向结论才补挂证据，否定、低置信、格式错误或网络失败都保持 provisional，不触发按排名强制分类。
- 自动挂接与语义复核都不能增加模型给出的 `match_score` / `confidence`，不能补造视觉值，也不能绕过颜色、排除项、独立证据、NeoRetro 特殊门槛或标签关系。复核后仍由同一确定性编译器和最终校验器从零闭环。
- 成功追踪分别记录自动挂接数、复核 Agent 执行数、接受/拒绝字段数、恢复标签数、错误数和具体决定；它与原有“校验失败后的局部 JSON 补丁”分开统计。

## 2026-09-02：风格弱引用先裁剪再重新闭环

- 低置信、无值、无证据或不在当前风格 allowlist 的额外字段不再直接导致整个标签降级；宿主只把该引用从风格证据链移除，原字段继续保留在设计 DNA 或不确定项中。
- 裁剪后从零重新检查决定锚点、独立辅助字段、证据数量、区域闭环、规则覆盖、颜色要求、排除项、特殊门槛和标签关系。只有剩余强证据仍完整时才能保持 confirmed，不能按候选排名强制分类。
- 必需字段和注册表特殊硬门槛不可裁剪。NeoRetro 的独立线索族与 `DET-17=历史造型化` 继续由宿主确定性复核，缺失时必须降级。
- 裁剪不增加 `match_score` 或 `confidence`，也不重新调用模型；编译报告和成功追踪分别记录弱引用裁剪数与最终风格降级数。

## 2026-09-02：宿主保守整理字段值与风格证据闭环

- 大模型先确定主体视角与 `active_profiles`，再通过宿主工具获取允许字段；只判断图片实际可观察、风格硬判需要或用户明确关注的字段，避免把 192 个字段都变成单次推理负担。
- profile、必要视角、静态元数据、统计、排序和不确定项镜像继续由宿主负责；显式别名、合法 enum 的单键 `label` 包装、关系描述中的标准关系词和规定离散刻度可确定性归一化，不能无损归一化的值只能转为未知或移除，不能发明替代视觉事实。
- confirmed 风格的字段角色、可用值、区域证据与规则闭环由宿主复核。证据不足时保守降为 provisional 并重建候选与组合关系，不再要求模型为了保住既有标签重新生成整份 JSON。
- 最终校验问题映射回模型观察 JSON Pointer；模型只接收仍需视觉/语义判断的局部问题。局部修复失败后，宿主可删除无法判断的字段或降级未闭环风格，完整观察重生成仅保留给结构不可解析的情况。
- 成功追踪继续记录推理指标；失败追踪另存完整原始响应、模型观察、编译结果、源路径映射和结构化问题。任务列表只暴露可读诊断摘要与诊断编号，详情文件不进入业务结果集。任务去重仍不实施。

## 2026-09-02：模型只输出精简观察，完整结果由宿主编译

- 模型阶段契约改为 `design_dna_multitag_observation_v1`，只保留图片事实、字段 ID/值/区域/证据、风格硬判、关系理由、不确定性和业务摘要；最终结果继续使用 `design_dna_multitag_extraction_v1.1`，因此现有 API、结果文件和前端无需迁移。
- 字段/风格静态元数据、模块清单、规则计数展开、dominance 归一化、统计、排序、confirmed 候选镜像、关系类型及可从规范字段推导的证据引用统一由幂等 Python 编译器生成。编译器不得改变视觉值、风格硬判、关系理由或凭空创造证据。
- 低置信 `uncertainties` 自带可观察性、置信度和证据；宿主可据此创建缺失的低置信设计字段，再生成最终不确定项镜像，避免模型维护两个耦合数组。
- 校验错误分为 deterministic 与 semantic：前者视为宿主编译缺陷，不消耗模型调用；后者优先通过受限 JSON Pointer 补丁修复，失败后最多执行一次完整观察兜底。
- DeepAgent 的稳定 Skill、协议、模型参考包、知识库和模型 Schema 作为版本化系统前缀预装，以便 provider Prompt Cache 复用并避免逐文件工具调用；`skills` 绑定仍保留，历史单标签 Skill 继续禁止访问。
- 成功追踪记录 Agent/LLM 请求、Token、网络重试、编译与语义修复指标；provider SDK 内部重试不可观测会被显式标记。任务去重本阶段不实施。

## 2026-09-02：当前 DNA 提取应用链路切换为扁平多标签 Skill

- 当前 DNA 提取 DeepAgent 只执行 `multimodal-design-dna-multitag-extractor`；系统提示明确禁止激活历史单标签 Skill，文件权限同时拒绝读取历史 Skill 包，避免两个输出契约混用。
- 大模型只返回精简 observation v1 JSON，不得写入 `derived_style_presets`；应用层按上方新决策编译完整 v1.1 结果，再调用 Skill 保存入口完成组合派生、最终 Schema 与语义校验。
- 完整详情 JSON 继续保持 Skill 原始契约；业务视图由宿主确定性转换为 `design_dna_multitag_business_view_v1.0`，增加所选模型和来源版本，但不向严格的完整结果写入应用字段。
- 业务与前端展示以同层 `style_tags` 为唯一已确认风格结论，dominance 只表示组合内视觉占比，不恢复主/次或一/二级语义；派生组合单独展示且不占标签名额。
- 历史单标签结果文件不批量改写；结果摘要保留兼容读取，详情中的旧字段作为历史扩展信息展示。

## 2026-09-02：组合预设由宿主确定性派生

- 模型只输出原子标签和可追溯 DNA，不读取组合预设注册表，也不生成 `derived_style_presets`。
- 宿主在模型输出后仅根据 confirmed `style_tags[].style_id` 执行 Python 规则匹配，并在最终校验前覆盖写入派生数组；候选、分数、图片语义和模型文字不参与计算。
- 模型阶段 Schema 与最终结果 Schema 分离；最终校验器重算派生值，拒绝缺失、伪造或过期内容。
- 组合预设可用于结果展示和查询，但不进入 `style_tags`、不占 dominance，也不能反向补足 DNA 或风格证据。

## 2026-09-01：命名风格组合与原子提取标签分离

- 玩趣构成、角色拟态、气室膨胀、透明层叠、解构拼装、数字故障、粗野原块和制作式不规整作为可由单图证据独立闭环的原子标签进入活动注册表。
- 赛博、孟菲斯、萌系、软糖、复古未来等宽泛命名只维护为查询组合预设；预设由已确认的原子标签计算，不写入 `style_tags`，不参与硬门槛，也不反向补足证据。
- 原子标签继续使用稳定 ID、独立权重和成对关系仲裁；组合预设可独立扩展而不改变提取 Schema 或历史标签语义。

## 2026-09-01：扁平多标签作为独立 Skill 并行演进

- 保留原 `multimodal-design-dna-extractor` 及其现有输出不变；新 `multimodal-design-dna-multitag-extractor` 仅在用户点名或明确要求扁平、多标签、无主次时触发，不自动替换现有应用链路。
- 结果层只输出 0～3 个同层 `style_tags`；每个标签独立通过硬门槛、决定锚点、辅助证据、颜色与排除规则，多标签不是强制目标。
- `candidate_ranking` 显式区分 `confirmed|provisional|rejected`；已确认标签使用 dominance 表达组合中的视觉主导度，排名和主导度都不恢复主/次分类。
- 后台保留多归属 facet 和标签关系图，但 facet 不进入输出层级。所有已确认标签对必须唯一、完整地裁决；默认同区域同机制需仲裁，跨区域或独立机制才可共存。
- conditional 同区关系使用 `same_region_coexistence` 显式区分禁止共存与独立证据共存；独立模式必须同时具备双方独占核心字段、独占字段证据及覆盖两侧的仲裁证据，不能靠同一物理事实换字段 ID。
- 只有可独立检索的 atomic 标签参与风格相似度；零权重 composite 必须具有明确 `requires` 依赖。身份信息归入 `IDG-05/07/09`，不占用风格标签名额或 dominance。
- 复古表达不再由普通组件字段名推断；新增受控字段 `DET-17 细节语法角色`，只有可见证据支持的“历史造型化”值才能通过 NeoRetro 表达门，且该值不证明真实年代或来源。

## 2026-09-01：Design DNA 使用稳定 ID、规范字段与证据优先判定

- 一级风格只作导航；二级风格使用不可变 `style_id`，显示名、别名和迁移关系独立维护，允许改名、合并与拆分而不破坏历史结果。
- 风格确认必须满足硬门槛、决定性锚点、独立辅助证据且未命中硬排除；易混风格通过集中混淆组仲裁，语义坐标只在硬判后排序。
- 扩展 DNA 是唯一规范字段体系；原 MD 六维仅由宿主兼容适配器派生，模型输出空兼容槽，不再重复提取或计分。
- 同一字段 ID 跨品类不得改义。通用核心字段由品类 profile 选择性启用，品类专属字段保持独立 ID。
- 状态拆为 `applicability_status`、`observability`、`computation_status` 三轴，`evidence_mode` 固定字段取值方式；不得以“不适用”代替不可见或不可计算。
- 当前单图 Skill 不激活 multi-face、参考或趋势 profile；M15 为 `profile_not_applicable`，core 内参考计算字段缺参考库时才是 `not_computable`。
- 当前结果显式保存 `active_profiles`；字段必须命中已激活 profile 并满足必要视角，非直接字段只有必要视觉输入可见时才能标为 `computed`。
- 单图只输出视觉材质和工艺候选，不把真实成分、工艺或随角变化写成图像事实。
- 风格锚点和辅助命中必须显式引用本次已观察或已计算的规范字段；颜色为 required 的风格不得以 `not_applicable` 绕过门槛。
- 每个活动风格在机器注册表分别维护决定字段与辅助字段 allowlist；真别名只做同义读取，兼容推导固定 `decision_use=none, weight=0`。
- 纯字符串标签集合统一使用 `multi_label`，结构化/混合集合使用 `list`；`computed derived` 必须闭合全部注册源字段及其证据，派生字段不承担硬门槛。
- Skill 只产生 JSON，应用层继续统一执行确定性校验、保存和业务视图转换。
- 业务视图按源 Schema 分别解释 M04/M10，避免把 v4 组件拓扑当品类字段、把通用文字图标当品牌识别。

## 2026-08-31：统一管理模型目录与调用入口

- 所有可用模型及其 `model_provider` 统一维护在 `app/services/llm/catalog.py`。
- 业务模块必须通过 `app.services.llm` 创建或调用模型，不直接实例化供应商 SDK。
- Claude 模型使用 Anthropic 协议；当前 GPT、MiniMax 和 Qwen 模型使用 OpenAI 兼容协议。

- 模型 Key 和网关地址只从 `LLM_KEY`、`LLM_URL` 读取，调用方不能覆盖连接参数。
- 前端通过 `GET /api/v1/llm/models` 获取目录中的可选模型，接口不返回凭据或网关地址。

## 2026-08-31：图片与结果先使用文件系统存储

- 当前阶段不接入 SQL 数据库；上传文件保存在 `data/uploads/<image_id>/`，成功结果保存在 `data/result/`。
- 上传元数据与图片一同保存，因此服务重启后仍可恢复素材列表。
- 任务状态暂存在后端进程内；服务重启会丢失运行中和历史任务状态，但已上传图片及成功结果不受影响。
- 结果列表只展示同时存在完整结果和 `_business_view.json` 的成功提取，避免暴露半成品。
- 每个成功结果在 `data/result/.metadata/` 保存追溯旁路文件，不向严格的 Skill 输出 Schema 增加字段。

## 2026-08-31：每张图片独立运行 Design DNA Skill

- 使用 DeepAgents 的 `create_deep_agent`、`FilesystemBackend` 和原生 `skills` 参数加载项目 Skill。
- 单次 Agent 执行只接收一张图片；批量和文件夹任务由应用层逐张串行调度，单图失败不阻塞同批其他图片。
- Agent 只读项目 Skill 和参考资料，不允许写文件；应用层统一执行 Schema 校验、语义校验、结果保存和业务视图转换。
- 模型输出校验失败时最多携带确定性错误修复一次；低置信字段数量等可计算统计由应用层重算，不消耗模型修复轮次。

## 2026-08-31：长推理使用流式连接并异步展示

- DeepAgents 完整技能执行可能包含多轮文件读取和长结构化输出，因此 API 以后台任务启动，前端轮询任务状态。
- 模型客户端启用流式响应，避免网关前置代理因长时间没有响应体而触发 524。
- Anthropic provider 使用兼容客户端，将网关字典型 `context_management` 流事件转换为 LangChain 可序列化对象；OpenAI provider 保持标准 LangChain 客户端。

- 确认弹窗只负责确认任务范围，提交后立即关闭；长任务进度在工作台中持续展示。

## 2026-09-01：开发外网访问使用 Cloudflare Quick Tunnel

- `start.sh` 将 Vite 前端作为唯一 Tunnel 源站，后端继续只监听本机并通过 Vite `/api` 代理访问，不直接暴露后端端口。
- Quick Tunnel 无需账户凭据，启动后生成动态 `*.trycloudflare.com` 地址，仅用于开发和临时验证；固定域名与访问控制后续使用 Named Tunnel 配置。
- Tunnel 与前后端使用同一进程生命周期，任一进程退出时统一清理，避免遗留公网入口。

## 2026-08-31：开发环境由根目录脚本统一启动

- 根目录 `start.sh` 并发启动 FastAPI 与 Vite；使用的 conda 环境以后续 Python 3.14 决策为准。
- 任一服务退出或用户按 `Ctrl+C` 时，脚本统一终止另一个服务，避免遗留后台进程。
- 默认端口为后端 8000、前端 5173；可通过 `DESIGN_AI_BACKEND_PORT` 和 `DESIGN_AI_FRONTEND_PORT` 覆盖，Vite 代理目标随之更新。

## 2026-08-31：素材与提取结果采用独立删除生命周期

- 删除素材只清理 `data/uploads/<image_id>/`，不级联删除已完成的提取结果；正在等待或执行提取的素材返回冲突，避免任务中途丢失输入。
- 每条新结果在 `data/result/.images/` 保存最长边 480px 的独立 WebP 缩略图。旧结果首次读取时可通过追溯哈希从素材库补齐，因此素材删除后历史结果缩略图仍然可用。
- 删除提取结果会同时清理完整详情、业务视图、追溯元数据和独立图片，删除范围严格限定在该结果 ID 拥有的文件。
