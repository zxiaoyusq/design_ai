# 架构决策

## 2026-09-09：网页高潜趋势复用轻量 Skill 与单步 DeepAgents

- 用户补充要求以独立消息进入每一归纳/汇总阶段，作用于关注方向与表达，不作为研究证据；日期范围仍由页面参数确定。与完整Skill一起预留输入空间并冻结到任务消息，旧任务缺少prompt时按空文本兼容。
- 应用层驱动已有3.0流程，DeepAgents只执行本包归纳或最终汇总；每包新建上下文，不用额外的总控模型往返。通过StateBackend绑定仅含目标Skill的虚拟目录，并冻结完整Skill、实际消息、模型参数和版本。单步中间件移除框架默认工具/长提示，仅使用已绑定Skill和阶段要求，防止隐式文件访问、委派及多次推理。
- 网页请求使用明确起止日期（两端包含），全部有效用研不跟随趋势日期筛选；无日期趋势排除。网页默认24次且可在1–100间调整；Skill CLI默认12次保持不变。按包含Skill上下文的48,000字符预算预估，超过调用上限在调用模型前停止；网页暂不跨任务共享模型笔记缓存。
- 沿用DNA模块的后台执行及轮询交互，额外将网页任务状态存盘。当前面向单进程本地服务（启动时保持一个worker），活动任务互斥；服务重启不自动续发收费调用。模型错误立即停止，已完成笔记保留；正常截断、未知引用等通过Skill交付部分结果，不追加审核或内容修复。
- 图片只从结果关联索引按序号提供同源URL，限制研究目录及栅格图片扩展名，并解析软链接后检查边界。模型始终只接收文本；结果页安全渲染Markdown文本节点，显示的图片不构成视觉分析或认可判断。
- 真实模型次数由LangChain回调记录，阶段尝试数独立保留；provider缺失用量不估算。微型假模型验证证明编排与界面可用，不宣称实测语义质量、性能降幅或真实Token费用。

## 2026-09-08：趋势归纳改为轻量设计启发流程

- 目标改为发现趋势与用研的明显设计交集。用户不要求严格的同机制证明、独立审核或全量反证；这些步骤从新任务默认路径删除，而不是通过调大单批token维持八阶段结构。
- 3.0只保留原始文本打包、方向笔记、一次成稿。输入小则跳过笔记直接成稿。笔记不要求逐记录观察/覆盖/跳过数组，综合任务只读摘要和代码提供的来源侧及用户信息，来源编号由代码展开；不产生候选×证据的组合任务。
- 中间结果允许普通Markdown，最终JSON由代码编译。只保留资料范围、来源ID存在、引用用户去重和路径存在等轻量检查，不做语义通过率门槛。未知编号不猜改，缺图置空，缺标题保留正文；格式和内容问题不触发整批模型重写。
- 总调用预算在准备前预估并在自动执行时持久限制；服务重试最多一次且消耗同一预算，最后成稿预留一次额度。资料或回复缺失时标明partial/empty，不能以退出码0宣称完整研究。默认输出较短，确需更多内容再由用户指定；不自动扩大到超大上下文。
- sources.json保存原文一次，结果只引用编号、文件指针与图片路径。笔记缓存按实际消息、模型配置和3.0规则匹配，不复用2.x细粒度观察缓存。宿主只启动脚本、处理真正阻塞和读取结果，不逐批协调或在普通运行扫描长会话日志。
- 用研补充仍以用户议题为主，代码仅在已引用用户严格超过分母一半时称多数；未覆盖趋势是已读摘要判断，不要求逐文章证明，也不表示市场空白。摘要可能遗漏细节，这是轻量启发分析的适用边界，不承诺全量观点覆盖。
- 新pipeline.py prepare默认3.0，旧manifest续跑路由旧实现；pipeline.py legacy显式访问旧命令。旧core.VERSION、历史任务、缓存键及旧ZIP保留，3.0另记版本与分发包。
- 验证默认微型代表夹具与假适配器；未经明确要求，不再做前20用户、全量或超大输入模型回放。小样本只证明流程可运行，不证明实际速度、token降幅和全量语义质量。

## 2026-09-08：模型调用观测与输入输出总量分开留痕

- 后端适配器追加可选 `observability.schema_version=1`，保留原协议和总 token 字段。LangChain 流回调仅观测客户端收到内容块的时间，不改变原 invoke 聚合、模型参数、消息、超时或重试。
- 分段时间从 invoke 前开始，记录首回调、首段非空白可见文本和调用结束；错误路径保留已观测时点，未收到的时点为 null。首段前可包含连接、服务排队、输入处理及缓冲，不能标为纯排队，后段也不能冒充服务端纯生成时间。
- 缓存输入和推理输出只读取 provider 已报告的细分，分别属于原输入/输出总量；缺失为 null，保留真实零值，不再次加总。旧调用无分段数据时不反推补造；复盘按新旧采样范围分别说明。

## 2026-09-08：显式长引文通过代码无损分包恢复

- 本轮 20 用户运行发现：模型已正确逐字引用 658 字原文，但单观察超过 600 字及 20 个图片角色，后续模型补齐反而出现句子拼接与非法维度。此类容量问题由独立版本 `extract_metadata_v5` 处理，模型原有契约、Prompt 和语义缓存键不变。
- 仅对已核实的显式连续原文、合法来源字段/维度/立场/角色执行完整句末分包；各片段不超过原契约上限，全部片段逐字拼接必须等于原引文，原角色完整分配，总观察预算仍须满足。省略 quote、正文被改写或单句过长等不由代码猜补。
- 记录原观察、原文哈希、Unicode 字符偏移、每片段角色及前后差异。旧请求、原始回复、失败日志及失败额度保留；已失败的合法原文可零模型调用恢复，不把新片段当作模型新生成的语义。

## 2026-09-08：提取传输格式与语义证据分离

- 2.3 新运行的 extract 模型输入采用 `extract_table_v1`：记录行按列定义排列，完整语境使用共享行且字段名只列一次，画像按用户去重。只压缩结构，不删改原文或上下文；缺失字段与 null 分开编码，额外字段保留。默认32来源/64观察的容量限制不扩大。
- 规范来源 ID 只保留在原任务及程序内部；创建任务时冻结 `transport_aliases`，模型回传短 ID。补齐子集继承映射并核对，没有重新编号。恢复、历史整组复用和诊断使用实际 attempt 的有效子集；未知或越界 ID 交严格校验，不猜配。
- 解析后先做确定性 ID 还原，再做现有元数据及原文校验。原回复、传输版本、映射摘要、逐项转换和结果摘要保留追溯，接受和缓存仍保存完整来源 ID；图片编码与引文不改。多次调用编译的凭证规则保持不变。
- 传输排版与语义缓存分开版本化，未改变的语义规则、完整原文、画像与模型配置仍可复用旧用户提取缓存。原2.1/2.2运行使用对应旧包续跑，不覆写已发请求。实际字符节省经同批比对；未调用真实模型就不声称实际token费用、延迟或质量改善。

## 2026-09-08：最终输出取消验证问题，补充方向以多数用户提及的议题为主

- 成卡契约升级至 2.2.0，删除 `validation_questions`，内部引用校验、反证和单卡审核继续执行。旧运行和接受凭证不迁移；旧包保留，当前预览只消费既有数据。提取契约、Prompt 和模板未变，因此把提取缓存版本与成卡版本分开，保留 2.1 内容键并重新校验缓存。
- 用研补充方向独立于双侧主卡筛选，读取全部已提取用户观察而非只看主卡引用或与趋势匹配的主题。代码组织有完整问答的小包；宿主复用已有语义判断，核对方向归属及全部选中趋势的语义覆盖，代码负责引用保真、人数、占比、路径与产物更新，不新增逐记录模型提取。
- 完整运行分母为全部有文本可归属用户，部分预览分母为明确的已处理用户。计数按用户去重、严格超过一半才发布。人数只表示已核对的主题提及下限，接受、拒绝和条件均算提及，不能写成共同偏好或自发需求率。趋势“未提及”仅限本轮所选文本；覆盖不确定或已有提及不发布。
- 最终 `user_research_gaps` 以用户方向、差异、证据、统计和图片关联为主体，替换未入选文章清单。Markdown/HTML 不介绍未选文章，逐趋势覆盖核对仅作为结构化追溯。原 `complete` 继续表示主卡队列停止条件；另增 `user_research_gaps_status` 与 `deliverable_complete`，避免补充尚未核对时冒充全部交付完成。

## 2026-09-08：用户要求先查看输出时，部分数据预览与完整研究分开保存

- 原运行按用户要求暂停，保留全部未完成任务、失败记录与已接收凭证。预览只消费已完成用户提取，并明确标注本次会话直接阅读的趋势源摘要，不伪造正式趋势提取或八阶段审核凭证。
- 证据索引提取为纯函数 `build_evidence`，完整流程仍以全部提取结果调用；预览显式传入已完成子集，原函数的全量校验路径不放宽。
- 预览独立输出 JSON/JSONL、Markdown、静态 HTML、范围、校验与用量文件，状态为 `preview_from_partial_data` / `preview_complete`，`parent_pipeline_complete=false`。逐字引用、人数去重和图片路径由代码核验；不将选中引用人数写成全部样本支持率。
- 原模型提取保留实际调用来源；本次会话归纳没有可核验的精确模型标识时如实留空，不冒充后端模型快照。后端 API 用量与不可得的当前会话用量分开描述，原完整运行无完成标记。

## 2026-09-08：代码校验先恢复 JSON 与完整记录组，仅补齐语义缺口

- JSON、字段、原文引用与完整覆盖始终由代码校验。模型原文解析前只允许移除完整 JSON 围栏、外围 BOM/空白和字符串外尾逗号；重复键、非有限数值、缺失语法、截断和散文包裹继续拒绝，不猜补正文。
- 对 extract 的历史回复按来源收集完整记录组，逐组严格校验并选择最新合法组；不删去同记录内的坏观察或冲突跳过项，不跨尝试拼接同一记录的判断。保留原正式 jobs/requests 与所有实际尝试。
- 有部分合法记录时，只针对原文未改写的剩余记录生成有效子请求；保留原任务 ID，消息只包含缺口，观察预算扣除已保留观察。默认最多两轮补齐，可设 0–2；传输重试冻结相同子请求和轮次，同任务传输失败额度仍为 3，历史校验计数不清零。崩溃恢复从已落盘请求补记轮次。
- 原组与补齐回复由代码编译，必须重新通过原任务全量覆盖和总预算校验。原始完整组已能覆盖时零调用恢复；全批没有合法组时不开额外整批重试。
- 编译凭证使用 `execution.mode=compiled_record_repair`，逐来源保留实际请求、模型、时间、原回复与摘要，不能冒充一次模型调用；不提供虚构的单次消息摘要，因此不进入现有单调用提取缓存。用量从真实 attempts 逐次计入，编译凭证不重复累计。
- 核心模型契约继续为 2.1.0；宿主规则为 `2.1.0:code-repair-3`。达到常规内容校验次数上限时，已有授权内先进行代码恢复和有界缺口补齐，不把规则上限自行解释成必须再次审批。
- 阶段规划错误单独保存为 `planning_failed`，保留续跑状态，不当作模型内容错误重试。最终来源类别由原 records 的明确 `primary_category` 派生，未知来源单独列出，不使用模型空派生值或用户问题类型猜品类。

## 2026-09-08：趋势提取的机械元数据错误由代码处理

- 在完整校验前增加有界整理：仅在原记录、证据字段及连续引文均有效时，移除引文中未完整出现的图片编码，并去重完全相同的合法维度。裸数字不补写图号前缀，不猜测图片别名，不修改引文、立场或不同维度。
- 空用户回答仅在同记录全部观察均为合法 unclear、无非空引文/图片角色、无 skipped 冲突时由代码转为一次 skipped；不使用问题补证，不填补模型遗漏，也不把原文中的“不确定”误判为空回答。
- 显式引文仅省略从 1 连续递增的列表编号时，代码构建带原始位置映射的去编号视图；只有唯一匹配完整连续项且恢复片段不超过 600 字时才回填原文。小数、断号、重复匹配、漏正文/否定词或截半项不处理；正文、标点和条件不改。
- 同一已知来源的 skipped 声明只在组内状态/原因完全相同且无 observations 冲突时去重，保留首项及逐条删除索引；不同状态或理由、未知来源或观察冲突不做选择，不填补覆盖。
- 模型原始 envelope、原文及既有失败 outcome 保持不变；接受的是另存的已校验视图，execution.normalization 留存规则版本、前后摘要与逐项差异。手动 accept 同样执行整理，并在凭证内保存 original_response。
- 已失败批次若能用原回复通过整理及完整校验，续跑直接恢复，单独记录 recovery，保留失败额度与原始调用用量；恢复操作新增模型调用为零，token 不重复累计。无法机械修正的问题仍遵守有限模型修复规则。
- 提取失败后的模型修复提示由代码补充逐观察诊断：保留原首个错误，最多列 8 处，反馈不超过 4000 字符，不选择引文或修改原回复，也不冒充全局覆盖校验通过。宿主修复提示版本升至 repair-2，传输重试复用同一消息，失败额度保持不变。
- 整理规则使用独立版本 extract_metadata_v4；当前 2.1.0 模型输入/输出契约不变，支持本轮安全续跑。旧版本分发快照保留，更新的可复制包另存 normalization 后缀并同步默认包。

## 2026-09-08：趋势 Skill 2.1 将首次提取改为紧凑语义判断

- 首次提取采用三个预算：默认每批至多 32 条来源、16,000 个完整消息字符、64 条观察。预计输出量按正文长度保守分配位置，长文缩批，未提取语义不能用代码关键词筛除。预算是运行配置，可调整；字符量不是模型 token。
- 模型只输出必需的 record_id/dimensions/stance，以及必要的连续 quote、非默认 field 和 image_roles。省略 quote 表示完整原文，超过 600 字必须显式引用；不再要求逐字复述后又生成 claim/context/user_value。skipped 解释无观察的来源，代码验证观察记录与 skipped 全覆盖，再恢复兼容输出的 coverage。
- 接收凭证保存原始紧凑回复；恢复字段仅为确定性派生，不伪称模型生成。兼容输出中的 claim 等于源引文，空解释字段不表示原文没有场景或条件。后续模型输入过滤重复派生字段，主题也必须回看完整源问答；source_records 与 profiles 按来源和用户分别去重。
- 图片由原来源和当前引文匹配编码、关联路径；未明确判断的对象角色保持 unclear，不能把整句反对传给比较图片。不同条件/态度/对象仍可拆观察，不为减少输出合并相反立场。
- 新提取契约和缓存命名空间使用 2.1.0，保留旧版分发包；旧运行不能由新协议续跑或手改迁移。版本更新不自动触发全量模型研究，先用可复跑的相同输入请求对照和独立小样本验证。


## 2026-09-08：趋势 Skill 2.0 使用逐记录缓存、主题候选和分类恢复

- 提取契约改为多维 observations 与明确的图片提及角色；与 1.0 不兼容，因此新版本使用新运行，旧分发包保留为 `dist/skills/design-trend-synthesizer-1.0.1.zip`。不修改旧运行、原始模型回复或源数据来迁就新契约。
- 用户 extract 结果按完整记录文本、画像、请求模型及参数、提取规则与契约版本缓存。只有宿主声明的模型配置与运行一致且提供有效消息哈希时写缓存；复用再次严格校验、保留原调用链，图片路径及源指针按当前输入重算。候选和最终结论不跨日期范围复用。
- 在候选前增加有完整成员覆盖的用户主题归纳，在合并前增加独立候选依据核对。候选只使用有来源的主题摘要及分立场代表，分别解释趋势、用户和共同设计原则；程序保留未代表、未配对及暂缓清单。最终反证仍覆盖候选全部维度，不把代表选择当作全体用户支持。

- `candidate_ranking` 显式区分 `confirmed|provisional|rejected`；已确认标签使用 dominance 表达组合中的视觉主导度，排名和主导度都不恢复主/次分类。
- 后台保留多归属 facet 和标签关系图，但 facet 不进入输出层级。所有已确认标签对必须唯一、完整地裁决；默认同区域同机制需仲裁，跨区域或独立机制才可共存。
- conditional 同区关系使用 `same_region_coexistence` 显式区分禁止共存与独立证据共存；独立模式必须同时具备双方独占核心字段、独占字段证据及覆盖两侧的仲裁证据，不能靠同一物理事实换字段 ID。
- 只有可独立检索的 atomic 标签参与风格相似度；零权重 composite 必须具有明确 `requires` 依赖。身份信息归入 `IDG-05/07/09`，不占用风格标签名额或 dominance。
- 复古表达不再由普通组件字段名推断；新增受控字段 `DET-17 细节语法角色`，只有可见证据支持的“历史造型化”值才能通过 NeoRetro 表达门，且该值不证明真实年代或来源。

## 2026-09-01：Design DNA 使用稳定 ID、规范字段与证据优先判定

- 一级风格只作导航；二级风格使用不可变 `style_id`，显示名、别名和迁移关系独立维护，允许改名、合并与拆分而不破坏历史结果。
- 风格确认必须满足硬门槛、决定性锚点、独立辅助证据且未命中硬排除；易混风格通过集中混淆组仲裁，语义坐标只在硬判后排序。
- 扩展 DNA 是唯一规范字段体系；原 MD 六维仅由宿主兼容适配器派生，模型输出空兼容槽，不再重复提取或计分。
- 同一字段 ID 跨品类不得改义。通用核心字段由品类 profile 选择性启用，品类专属字段保持独立 ID。
- 状态拆为 `applicability_status`、`observability`、`computation_status` 三轴，`evidence_mode` 固定字段取值方式；不得以“不适用”代替不可见或不可计算。
- 当前单图 Skill 不激活 multi-face、参考或趋势 profile；M15 为 `profile_not_applicable`，core 内参考计算字段缺参考库时才是 `not_computable`。
- 当前结果显式保存 `active_profiles`；字段必须命中已激活 profile 并满足必要视角，非直接字段只有必要视觉输入可见时才能标为 `computed`。
- 单图只输出视觉材质和工艺候选，不把真实成分、工艺或随角变化写成图像事实。
- 风格锚点和辅助命中必须显式引用本次已观察或已计算的规范字段；颜色为 required 的风格不得以 `not_applicable` 绕过门槛。
- 每个活动风格在机器注册表分别维护决定字段与辅助字段 allowlist；真别名只做同义读取，兼容推导固定 `decision_use=none, weight=0`。
- 纯字符串标签集合统一使用 `multi_label`，结构化/混合集合使用 `list`；`computed derived` 必须闭合全部注册源字段及其证据，派生字段不承担硬门槛。
- Skill 只产生 JSON，应用层继续统一执行确定性校验、保存和业务视图转换。
- 业务视图按源 Schema 分别解释 M04/M10，避免把 v4 组件拓扑当品类字段、把通用文字图标当品牌识别。
