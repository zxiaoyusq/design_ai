# DNA V2：设计关系提取与冻结结果库

## 数据范围

`/dna-v2` 使用 `prism-design-dna-preparation` 的原生设计卡，不再把旧 R17／Sol R5 的字段结果作为本页的默认结果集。

初始结果集来自明确指定的冻结快照：

```text
data/result/dna_cluster_moodboard/sample1600_balanced_llm_20261010/preparation/prepared-manifest.json
```

该快照共有 1,600 张趋势图片、1,587 张至少有一张有效卡，合计 3,578 张卡（ID 1,513、CMF 2,065）。13 张无有效卡的图片保留逐图终态和原错误：12 张未选择可用对象，1 张模型请求超时。ID 覆盖 1,513 张原图，CMF 覆盖 1,528 张原图；卡数不等于图片数，结构冻结不等于审美或人工通过。

这些历史结果的实际 Prompt 为 `prism-relational-design-cards-20261010-v1`，请求模型为 `gpt-6.1-sol / high`，回执未报告实际模型标识。网页保留原始版本和未知信息，不把历史卡改写为当前 Prompt v2。

## 新图片提取

新任务只处理用户选择并确认的上传图片。网页调用 Skill 的原生 `run`，注入工程 `create_bounded_agent + create_chat_model` 执行器，通过统一模型目录和 `LLMSettings` 读取模型与连接配置，默认 `gemini-3.8-flash`。网页模型可选，Skill 的 Prompt、Schema、七组关系与风格规则保持冻结；不通过 Codex CLI 或 ChatGPT 认证转发，不因切换结果库自动启动模型任务或重新提取历史全量。

SDK 默认关闭重试，DeepAgents 限制一次无工具模型调用。Gemini 未显式指定推理强度时回执为 null，页面显示“按模型默认”；供应商实际模型及别名按回执保存，不把请求模型冒充实际模型。

每图至多 1 个 ID、2 个 CMF 对象；对象框、证据框、展示框、七组关系、同层风格候选、设计情绪及反向信号、设计感依据、限制和来源均保留。新请求使用当前 Prompt v2，原图和逐图原答、回执、模型设置与时间继续可追溯。

## 冻结与展示

- 一张原图在图库中占一条记录；ID／CMF 卡在详情中按对象切换，避免把同图的多个对象当作多张图片。
- 同一原图再次经用户确认提取时，默认显示最新快照；旧结果和完整证据仍可通过原结果 ID 读取。损坏的新增索引独立隔离，并在页面提示数量和原因，不影响原历史集。
- 展示框按冻结的归一化 `xywh` 映射到原图；放大查看完整原图不产生新的视觉证据，也不修改取景或原答。
- 关键词、分支、风格、状态筛选与分页只改变显示。历史失败和对象错误保留，未知不转成“没有”，设计卡有效不转成整板合格。
- 冻结结果不可在网页逐条删除。旧结果文件与旧提取器仍保留，其历史身份不被批量迁移或覆盖。
- 图片接口只从已登记结果索引取路径，原图 SHA 必须与冻结记录一致；不接受客户端传入任意文件路径。

## API 与存储

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/dna-v2/preparation` | 原冻结集覆盖统计、38 种风格目录、可选模型／默认模型、实际框架与传输、新任务数量及当前 Prompt 身份 |
| `GET /api/v1/dna-v2/results` | 原冻结集与本 Skill 新提取结果的一图一条摘要；支持 `query`、`branch=ID/CMF` |
| `GET /api/v1/dna-v2/results/{id}` | 原生设计卡、图片终态、对象错误和来源追溯 |
| `GET /api/v1/dna-v2/results/{id}/image` | 经身份校验的完整原图 |
| `POST /api/v1/dna-v2/extractions` | 用户确认后创建仅包含所选上传图片的任务 |
| `GET /api/v1/dna-v2/extractions/{id}` | 轮询逐图进度和终态 |

原历史集的网页 ID 为 `prep1600-{image_id}`；新任务为 `prep-{uuid}`。新任务原图、输入、原生运行和结果索引写入 `data/result/dna_preparation_web/`，不覆盖原冻结快照。新任务单图一个原生执行器，各任务共用最多两个图片槽位。原生计划显式保存运行模型、参数、执行器与依赖源码 SHA；默认 CLI 配置和工程 SDK 配置不能混用缓存，不修改模块全局模型。SDK 执行器保存实际多模态请求、原图字节、原回答、响应元数据、回执和已知／未知 Token 用量，Skill 负责原生编译与冻结；失败和未知用量不会被包装成完整成功或零费用。

列表首次加载只由原生 `prepared_header` 校验冻结容器、样本和卡文档，逐图打开详情时再由 `validate_frozen_cards` 验证该图的卡与原答、Prompt、回执和原图。这样不会在每次翻页时重复解析全部 3,578 张卡的证据；图片接口另核对原图 SHA。缓存以文件身份绑定，不在网页运行重新编写冻结字段。

## 验证边界

历史快照、原图与证据只读核对；执行器使用离线假模型和真实 DeepAgents 图验证边界。本次另按用户要求抽样一张趋势图片通过真实上传与提取任务 API 测试 Gemini 3.8，运行记录在 `.runtime/dna-v2-gemini-sample-20261021/`，每次尝试与失败分别保留。代码、浏览交互及单张真实测试不能证明全库提取准确，也不构成新的人工批准。

全量只读审计记录：`.runtime/dna-v2-snapshot-audit-20261021.json`。桌面／手机浏览验证及代表截图保存在 `.runtime/dna-v2-integration-20261021/`。
